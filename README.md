# OpenCAD STEP 뷰어·해석기

STEP(ISO 10303-21, AP203·AP214·AP242) 파일을 브라우저 안에서 읽고 B-rep 곡면을 삼각화해 3D로 보는 앱과 그 해석기입니다.
해석기는 DOM·WebGL에 기대지 않아 웹 워커에서 돌고, 결과 장면(`Scene3d`)은 [opencad-viewer3d](https://github.com/GyuTae-Kim/opencad-viewer3d)로 그립니다.
다른 CAD 커널이나 STEP 라이브러리를 쓰지 않고 공개 명세만 보고 새로 작성했습니다.

**앱 주소(배포 예정):** https://gyutae-kim.github.io/opencad-step/

함께 쓰는 저장소: [opencad-viewer3d](https://github.com/GyuTae-Kim/opencad-viewer3d)(3D 뷰어 코어) ·
[opencad-nc](https://github.com/GyuTae-Kim/opencad-nc) · [opencad-skp](https://github.com/GyuTae-Kim/opencad-skp)

## 할 수 있는 것

- Part 21 글 읽기(머리, 개체, 복합 개체, 문자열 부호)
- 압축 STEP: gzip(.stp.gz·.stpZ)과 안에 .stp·.step·.p21이 든 ZIP(저장·deflate, ZIP64) — `unpackStep`(`src/archive.ts`).
  STEP-XML(ISO 10303-28, .stpx)은 지원하지 않는다고 알려 줍니다.
- B-rep 곡면 삼각화: 평면·원기둥·원뿔·구·원환·B-스플라인·회전·밀기 곡면, 구멍 있는 면, 틈 없는 이음
- 조립(제품·인스턴스 변환), 색, 단위, 제품 나무(`StepProductNode`)
- 자리별 색 덮어쓰기(CONTEXT_DEPENDENT_OVER_RIDING_STYLED_ITEM): style_context(자리 변환 관계·NAUO·사상 항목)가 가리키는 자리에서만 칠한다
- 짧은 호(처진 높이가 허용 오차보다 작은 원호)도 두 토막 이상으로 나눠, 같은 꼭짓점을 잇는 현과 겹친 활꼴 면이 넓이 0으로 실패하지 않는다
- 레이어(PRESENTATION_LAYER_ASSIGNMENT, 레이어를 가리키는 INVISIBILITY) → `meta.layers`
- 제품 속성(제품 설명·판·정의 설명, 재질 이름·밀도, 사용자 속성 — PROPERTY_DEFINITION → 표현 항목, MATERIAL_DESIGNATION) → `StepProductNode.props`,
  자리의 세계 변환 → `StepProductNode.matrix`(밀도는 단위를 따라 kg/m³로, 단위가 없으면 값 크기로 g/cm³·kg/m³를 짐작)
- 와이어프레임·곡선 형상(GEOMETRICALLY_BOUNDED_WIREFRAME_SHAPE_REPRESENTATION의 GEOMETRIC_CURVE_SET·GEOMETRIC_SET,
  EDGE_BASED·SHELL_BASED_WIREFRAME_MODEL, 형상 표현 안의 독립 곡선 — 선·원·잘린 곡선·복합 곡선·B-스플라인 등, 선 색 CURVE_STYLE) → `scene.lines`(점은 `scene.points`)
- 표현 PMI(ANNOTATION_CURVE_OCCURRENCE·TESSELLATED_ANNOTATION_OCCURRENCE 등, ANNOTATION_PLANE·DRAUGHTING_CALLOUT 안까지)를
  그 부품 자리에 선으로, 의미 PMI(치수 값·± 공차, 기하 공차 크기·데이텀, 데이텀) 목록 → `meta.pmi`
- PMI 글자(TEXT_LITERAL과 아형, COMPOSITE_TEXT 안까지)를 내장 한 획 글꼴(`src/strokefont.ts` — 숫자·영문·기호 ± ° Ø ×·GD&T 기호)로 선분으로 그립니다.
  글자 높이는 TEXT_LITERAL_WITH_EXTENT 크기, 주석 양식의 BOX_HEIGHT, 없으면 2.5. 맞춤(centre·right·top)을 따릅니다(`src/pmitext.ts`)
- 내장 글꼴에 없는 PMI 글자(한글·일본어·중국어·그 밖의 기호)는 앱의 해석 워커가 기기 글꼴로 화면 밖 캔버스에 그려 윤곽선을 따라간 선분으로 그립니다
  (`src/app/glyphs.ts`·`src/glyphtrace.ts` — 글꼴 파일을 내려받지 않고, 글자마다 한 번만 그립니다). 다른 PMI 선과 같은 선 묶음이라 확대·단면·숨김·강조·그림 저장을
  그대로 따릅니다. 해석기만 쓸 때는 `glyphs` 선택으로 글자 모양을 주고, 주지 않거나 기기에 그 글자 글꼴이 없으면 빈 상자로 그립니다
- 의미 PMI ↔ 면: 모양 측면 → GEOMETRIC_ITEM_SPECIFIC_USAGE → 면, 복합 측면·데이텀 ↔ 데이텀 형체는 SHAPE_ASPECT_RELATIONSHIP으로 따라가 `semantic[].faces`(면 STEP 번호)
- 저장된 보기(CAMERA_USAGE → CAMERA_MODEL_D3·VIEW_VOLUME·보기 창): 대상·방향·투영·창 높이와 그 제도 모형의 표현 PMI → `meta.pmi.views`(`src/savedviews.ts`)
- 면 표(그물 삼각형 → B-rep 면, 면 종류·곡면 매개변수, B-rep 넓이·둘레와 정확한지) → `meta.faceTables`·`meta.meshFaceTable`(면 단위 고르기)
- 모서리 표(그물 윤곽선 `Mesh3d.edges`의 선분 → B-rep 모서리 EDGE_CURVE, 곡선 종류 직선·원·타원·B-스플라인, 원 중심·법선·반지름·호 각, 곡선 길이 적분,
  곡선 모서리 두 끝의 접선 — B-rep 곡선의 1차 도함수, 모서리 방향, 원호·타원 호의 틀 x축과 두 끝 매개변수 각(한 바퀴 원은 없음, 한 바퀴 타원은 틀 x축만)과
  B-스플라인 정의 — 차수·매듭·조절점·가중치·모서리 매개변수 구간, 수 512개까지 `curveStart`·`curves`)
  → `meta.edgeTables`·`meta.meshEdgeTable`(모서리 고르기·개체 측정·측정 접선 잠금 — 이음선은 윤곽선에 없어 표에도 없음)
- 닫힌 입체(닫힌 껍질, 실패한 면 없음, 삼각형이 틈 없이 맞물림)의 그물에 `Mesh3d.closed = true` — 단면에서 잘린 면을 채웁니다
- 닫힌 입체의 질량 속성(부피, 1차·2차 모멘트)을 화면용 삼각형이 아니라 B-rep 곡면과 모서리 곡선을 적분해 구합니다 → 면 표 `props`(`src/massprops.ts`).
  발산 정리로 입체 적분을 겉면 적분으로 바꾸고, 면마다 곡면 매개변수 공간에서 그린 정리로 경계 적분으로 바꿉니다. 평면·원기둥·원뿔·구·원환과
  회전 곡면(직선·원·타원·B-스플라인 윤곽 — 윤곽이 축과 한 평면에 있지 않아도 됨)은 안쪽 적분이 닫힌 식이라 직선·원·타원 모서리로 된 입체는
  반올림 오차 수준(상대 1e-14 안팎)으로 맞습니다. B-스플라인 윤곽은 매듭 구간마다 다항식이라 매개변수 공간 직선 토막을 매듭에서 나눠 적분합니다.
  B-스플라인 곡면과 B-스플라인 곡선을 민 곡면도 매듭 구간마다 (u, v)의 다항식이라, 안쪽 적분을 u 매듭에서 나눈 가우스로(u 구간이 많으면 다 덮는 구간 적분의
  누적 합을 v의 다항식으로 미리 구해 둠), 매개변수 공간 직선 토막을 u·v 매듭에서 나눈 가우스로 정확히 구합니다. 모서리 곡선 토막은 곡선 매듭에서 나눠
  7–15점 가우스–크론로드로 적분하고 둘이 어긋나면 반으로 나눕니다. 곡선 위 점은 토막 끝의 (u, v) 사이 짐작에서 가우스–뉴턴으로 곧장 곡면에 되짚고
  (마지막 점의 편도함수를 그대로 쓰고, 반올림 수준에서는 걸음을 줄여 다시 구하지 않음), 곡면에서 되짚기 허용치보다 멀 때만 격자 짐작까지 합니다.
  가중치가 있는 B-스플라인(NURBS)은 점을 더 쓰고 점이 적은 규칙과의 차이를 어림 오차로 남깁니다
  (NURBS 원기둥에서 어림 오차 상대 3e-12, 실제 오차 1e-16). 원·타원을 민 곡면은 원기둥처럼 닫힌 식입니다. 오프셋 곡면처럼 적분하지 않는 곡면과
  모서리 곡선이 곡면에서 멀어 곡면 적분의 어림 오차가 삼각형 쪽보다 큰 면은 그 면만 삼각형으로 재고
  꺾인 선과 곡선 사이 띠를 더해 겉면을 닫으며, 삼각형과 곡면 사이 거리로 어림 오차를 함께 남깁니다. 삼각형 부피와 크게 어긋나면 삼각형 값으로 되돌리고,
  적분이 오래 걸리면(기본 1.5초 + 삼각화 시간의 절반을 넘으면) 남은 입체는 삼각형 값과 어림 오차를 씁니다(`propsBudget`, `meta.stats.propsTimedOut`).
  적분은 삼각화와 떼어 둡니다: 삼각화하면서 면마다 적분할 거리(곡면, 매개변수 공간 다각형, 경계 모서리와 곡선 매개변수)만 남기고
  `MassPropsJob`(`src/propsjob.ts`)이 따로 적분합니다. 앱 워커는 문서를 보인 뒤 면 단위로 나눠 적분하고, `stepToScene`은 예전처럼 끝까지 적분한 장면을 돌려줍니다
- 닫힌 껍질의 면 방향 맞추기: 경계 고리가 면 법선과 거꾸로 돈 면(곡면 법선 약속이 다른 프로그램의 파일 — 예: 압출 곡면의 u·v를 바꿔 씀)이 있거나
  부피가 음수면, 이웃 면이 같은 경계 선분을 같은 방향으로 쓰는지 보고 면 묶음을 뒤집어 바깥 법선으로 맞춥니다(`orientFaces` — 덩어리마다 부피 부호로
  바깥을 정해 빈 곳 BREP_WITH_VOIDS는 안쪽으로). 단일면으로 그리는 닫힌 입체에서 면이 사라지지 않습니다
- 주기를 한 바퀴 다 덮으며 이음선을 갔다 오는 띠 고리(원환 필렛 고리 등)는 FACE_BOUND 방향이 거꾸로 적혀도 구멍이 아니라 그 띠로 읽습니다
- 큰 부품의 작은 반지름 필렛처럼 성긴 현 안쪽에 점이 생겨 삼각형이 접히면(3D 법선이 곡면과 반대), 안쪽 접힘은 나누고 경계 현 때문이면
  그 면의 모서리를 더 잘게(현 높이 ¼, 두 번까지) 나눠 그 모서리를 쓰는 면만 다시 삼각화합니다(이웃 면도 같은 다각선이라 틈이 없음)
- 곡선 모서리 둘이 현 높이보다 좁게 나란히 가는 가는 띠 면처럼 경계가 스스로 엇갈려도 고리 점을 하나도 빼지 않고 삼각화해(`clipAll` — 엇갈린 자리의
  삼각형은 뒤집히지만 띠 너비만큼이라 아주 작습니다) 이웃 면과 틈이 생기지 않습니다
- 한 변이 한 점으로 모인 곡면(극점)에서 극점으로 들어가는 두 경계가 같은 접선으로 만나 폭이 아주 빨리 0으로 모이면, 다듬기가 나눈 점들이 3D로 거의 겹쳐
  바늘 같은 삼각형이 접히던 것을 막습니다: 극점 밖 두 점이 용접 거리의 10배보다 가까워지면 극점 둘레를 따로 떼어, 극점에서 곧게 나가는 빛살과 모든 빛살이
  함께 쓰는 깊이 줄로 나누고 나머지만 다시 삼각화합니다. 경계 다각선은 그대로라 이웃 면과 틈이 없습니다(로컬 표본 "아주 세밀" 품질에서 감기가 어긋난 입체
  4개 파일 → 0개, 같은 처리가 걸린 다른 6개 파일은 접힌 삼각형 6~11개 → 0개)
- 끊긴 파일(END-ISO-10303-21이 없거나 마지막 문장이 잘림)은 해석기 경고 맨 앞에 `TRUNCATED_WARNING`을 두고, 아는 곡면을 가리키는 개체가 없어
  못 만든 면은 "지원하지 않는 곡면"이 아니라 "읽지 못함(가리키는 개체가 없거나 값이 잘못됨)"으로 적습니다
- 큰 좌표(좌표 크기 1e4 단위 이상이면서 묶음 크기의 2000배 넘음 — 예: 공장·지도 좌표 1e5~1e6 mm)에 만든 형상은 묶음 가운데를
  `origin`으로 빼고 담아 float32로도 떨리지 않습니다(그 밖에는 예전과 같습니다)
- 틈·넓이·부피 검사(`watertightness`, `meshArea`, `meshVolume`)
- 공개 STEP 21개를 실패 면 없이 읽었고, NIST 시험 모형 9개는 모두 틈이 없습니다. 여러 CAD·커널이 내보낸 로컬 STEP 2,091개(내용이 같은 것 뺌)를
  세 곡면 품질(20°·10°·5°)로 훑어(`npm run sweep` — 개발 절) 예외·실패 면 0, 닫힌 껍질 3,119개가 모두 틈 없이 닫히는 것을 확인했습니다(보통 품질에서
  삼각형 감기가 어긋난 입체 72개 파일 → 0개, 접힌 삼각형이 0.1% 넘는 파일 35개 → 6개). 앱의 "아주 세밀" 품질에서 가장 오래 걸리는 파일(면 2,730개,
  삼각형 274만 개)은 12초쯤 걸립니다(데스크톱, 고치기 전 20초). 같은 표본(보통 품질)의 닫힌 입체 3,114개 가운데 2,808개는 질량 속성이 곡면 적분으로 정확하고,
  301개는 B-스플라인 같은 면이 섞여 어림 오차가 많아야 ±0.083%입니다(나머지 5개는 지름 0.4 µm 남짓한 퇴화 입체라 삼각형 값). 질량 속성은 문서를 연 뒤
  따로 적분하므로 문서 여는 시간은 적분을 넣기 전과 같습니다(표본 442개를 번갈아 잰 합: 적분 없이 8.9초, 지금 9.1초, 열면서 함께 적분하면 11.9초).
  회전 곡면도 적분한 뒤 지금 남은 표본 1,864개(보통 품질)에서는 근삿값 입체가 197개 → 177개로 줄었습니다(회전 곡면이 든 32개 파일 가운데 20개가 정확,
  12개는 B-스플라인 면 등이 섞여 어림 오차만 줄어듦). B-스플라인·민 곡면까지 적분하자 근삿값 입체가 177개 → 166개(파일 147개 → 136개), 가장 큰 어림 오차가
  ±0.083% → ±0.017%가 되었습니다. 값이 바뀐 입체 91개는 모두 예전 값 ± 어림 오차 안이고, 그 가운데 88개는 어림 오차가 좁아졌습니다(예: ±0.013% → ±0.00007%).
  근삿값이던 그 파일들의 B-스플라인·민 곡면 642개 가운데 577개(가중치 있는 면 284개 가운데 264개)를 곡면 적분하고 65개는 삼각형 쪽 어림 오차가 더 좁아 삼각형으로 잽니다.
  질량 속성 적분 시간은 그 147개 파일에서 합 3.1초 → 5.1초(중앙 7 → 13 ms, 가장 긴 파일 0.37 → 0.47초)이고 문서 여는 시간은 그대로입니다.
  남은 근삿값은 대부분 모서리 곡선(교선을 맞춘 곡선)이 곡면에서 조금 떨어져 생긴 것이라, 곡선 위 점을 곡면의 가장 가까운 점으로 다듬은 자리를 면의 경계로 적분하고
  그 경계에서 곡선까지 곧은 띠를 더합니다. 이웃 면도 같은 곡선까지 이으므로 겉면이 닫히고, 어림 오차는 곡선과 곡면 사이 거리를 반지름으로 한 관의 부피(모형의 허용 오차)로 줄어듭니다.
  모서리 곡선이 꼭짓점을 조금(1e-4 mm 안팎) 비껴 지나 면 경계가 꼭짓점마다 끊긴 곳도 꼭짓점 둘레를 메워 잇습니다.
  그러자 근삿값 입체가 166개 → 29개(파일 136개 → 19개), 가장 큰 어림 오차가 ±0.017% → ±0.000011%가 되었습니다. 값이 바뀐 입체 292개(파일 284개)는 모두
  예전 값 ± 어림 오차 안입니다. 적분 시간은 근삿값이던 136개 파일에서 합 3.5초 → 4.1초(중앙 7.0 → 7.5 ms, 가장 긴 파일 0.38 → 0.42초)입니다.
  "아주 세밀" 품질에서도 시간 한도를 넘는 파일이 없고(한도를 가장 많이 쓴 파일이 31%), 값은 보통 품질과 어림 오차 안에서 같습니다(B-rep 입체 2,887개의 상대 차 중앙값 1e-15).
  시간 한도(1.5초 + 삼각화 시간의 절반)는 입체를 시작할 때 보므로 입체가 하나인 파일은 한도에 걸리지 않고 끝까지 적분합니다(적분이 가장 긴 두 파일이 그렇습니다).
  B-스플라인 면 적분에서 곡선 위 점 되짚기를 다듬자(점마다 곡면 계산 8번쯤 → 3번쯤) B-스플라인 면이 많은 파일의 적분 CPU 시간이 30~39% 줄었습니다
  (가장 긴 두 파일이 이 컴퓨터에서 0.50~0.53초 → 0.34~0.37초, 고치기 전·후를 번갈아 세 번 잰 가운데 값). 표본 전체로는 적분 CPU 시간 합이 11% 줄었고,
  닫힌 입체 2,892개의 부피·무게중심·관성은 모두 예전 값과 상대 1e-14 안입니다(구한 길도 그대로).
  보통 품질에서 한도를 가장 많이 쓴 파일은 입체 81개짜리로, 마지막 입체를 시작할 때 0.54초를 써 한도(2.64초)의 20%입니다.
  한도가 삼각화 시간을 따라 늘어나서, 기기가 고르게 느리면 마지막 입체를 시작할 때까지 쓴 시간이 삼각화 시간의 절반을 넘는 파일만 걸릴 수 있습니다.
  로컬 표본 1,860개에서 그런 파일은 둘이고(입체 9·13개), 그 둘도 이 컴퓨터보다 48배 넘게 느린 기기에서야 남은 입체가 삼각형 값이 됩니다.

## 앱 쓰는 법

- **열기**: 제목 막대의 "열기"(Ctrl+O)로 `.stp`·`.step`·`.p21` 파일이나 압축 STEP(`.stp.gz`·`.stpZ`·STEP이 든 `.zip`)을 고르거나,
  창 어디에나 끌어다 놓습니다(여러 개를 놓으면 첫 STEP 하나). 압축은 워커가 "압축 푸는 중" 단계로 풀고, 정보 탭에 압축 형식·ZIP 항목·푼 크기를 보입니다.
  `.stpx`(STEP-XML)는 지원하지 않는다는 안내가 뜹니다. 같은 Part 21 글인 IFC(건축 BIM, FILE_SCHEMA가 IFC…)는 다 읽기 전에 IFC 뷰어로 열라고 알리고,
  끊긴 파일은 형상이 없으면 그것을 까닭으로, 일부만 읽혔으면 "파일을 다시 받아 여십시오" 알림을 띄웁니다.
  "예제 열기"는 우리가 만든 작은 조립 모형(받침판·블록 둘·핀 묶음, 레이어 셋, 받침판 PMI)을 엽니다.
  한 번에 문서 하나를 열며 새로 열면 바꿉니다. 큰 파일은 해석 중 덮개의 "취소"(또는 Esc)로 멈출 수 있습니다.
- **파일은 이 브라우저 밖으로 나가지 않습니다.** 읽기(웹 워커)와 그리기(WebGL2)를 모두 이 컴퓨터에서 합니다.
- **최근 문서**: 파일 고르기·끌어다 놓기로 잘 연 파일은 이 브라우저의 IndexedDB(`opencad-step` — 목록 `recent`, 파일 `recent-data`)에 새것부터 8개까지 남깁니다(60MB보다 큰 파일과 예제·`?open=` 주소로 연 것은 빼고).
  시작 화면의 "최근 문서"에서 이름·크기·시각을 보고 눌러 다시 열며, ✕로 하나씩 또는 "모두 지우기"로 지웁니다. 서버로 보내지 않고, 비공개 창처럼 저장소를 못 쓰면 목록 없이 그대로 씁니다.
  목록을 그릴 때는 파일 바이트를 읽지 않고, 누른 파일 하나만 읽습니다. 저장해 둔 파일이 없으면 목록에서 지우고, 잠깐 못 읽으면 항목을 남겨 다시 누를 수 있게 합니다.
  휴대폰 브라우저가 뒤로 간 탭을 버렸다가 다시 불러와도 파일 앱을 다시 거치지 않고 엽니다.
- **정면으로 보기·홈 뷰**: 고른 면을 작업 메뉴의 "정면으로 보기"(휴대폰 면 고르기 띠의 "정면")로 평면은 바깥 법선 쪽에서, 원기둥·원뿔·원환은 축 방향에서 맞춰 봅니다.
  표준 뷰 메뉴의 "홈 뷰"(Home 키)는 문서를 처음 열 때 맞춘 보기로, "지금 보기를 홈 뷰로"는 지금 보기를 홈 뷰로 정합니다.
- **보기**: 왼쪽 끌기 회전, 오른쪽·가운데 끌기 이동, 휠 확대, 터치 회전·핀치. 도구 막대에 전체 보기(F), 고른 부품 보기, 표준 뷰(1 앞 · 2 뒤 · 3 왼쪽 · 4 오른쪽 · 5 위 · 6 아래 · 7 등각),
  원근/평행, 그리기 모드(음영·음영+모서리·와이어프레임·X-ray·**숨은선 제거**·**단색**), 단면, 격자(F7), 뷰 큐브, 좌표축, 고르기(부품·몸체·면·모서리, 여러 개), 측정(두 점·개체, Esc = 지우기), 내보내기, 패널 열고 닫기가 있습니다.
  그리기 모드 메뉴(휴대폰은 보기 설정)의 선택: **숨은 모서리 점선**(숨은선 제거 모드에서 면 뒤 모서리를 흐린 점선으로 — 코어 `setRenderOptions({ hiddenEdges })`),
  **외곽선 강조**(화면 공간 실루엣 — `profiles`), **부품 색 구분**, **분해 보기**(아래).
  와이어프레임·숨은선 제거는 B-rep 모서리만 그리고(삼각형 변 없음 — 코어 `triangleEdges`) 모서리와 같은 1화소 외곽선을 늘 켭니다(코어 v0.7.2 `profiles: { width: 1 }`).
  모서리가 없는 매끈한 면(원환 고리·구)도 테두리로 보이고, 이 두 모드에서 "외곽선 강조"는 켜진 채 잠깁니다(다른 모드로 가면 고른 값으로).
  키는 캔버스에 초점이 없어도(입력 칸 제외) 듣습니다. Tab 키로 3D 보기에 초점이 오면 보기 안쪽에 테두리가 보입니다. 마우스·터치로 누르면 테두리가 사라지고(키보드로 초점을 준 뒤 눌러도), Tab으로 다시 오면 보입니다(코어 v0.9.1).
- **고르기 단위**: 도구 막대의 "고르기" 메뉴(단추 이름이 지금 단위 — "부품 고르기"·"몸체 고르기"·"면 고르기")에서 **부품**(기본 — 누른 형상이 놓인 나무 마디 통째),
  **몸체**, **면·모서리**(아래 "면 고르기")를 고릅니다. **몸체**는 한 부품 안에 입체(MANIFOLD_SOLID_BREP·BREP_WITH_VOIDS·면 모형 등 형상 항목)가 여럿일 때
  누른 입체 하나만 고릅니다. 해석기가 형상 항목마다 그물 하나를 만들므로 해석 결과는 그대로입니다. 이름이 없는 몸체는 "부품 · 몸체 2"로 부릅니다.
  숨기기·이것만 보기·맞춰 보기·STL/OBJ "고른 것"·속성 탭의 물리 속성(그 몸체만)에 그대로 쓰입니다.
  부품 단위로 3D에서 누르면 그 부품의 몸체를 모두 강조합니다(숨기기·격리가 쓰는 것과 같게).
- **제품 나무의 몸체 줄**: 몸체가 둘 이상인 부품은 나무에서 펼칠 수 있고, 펼치면 자식 마디 앞에 몸체 줄(형상 항목 이름, 없으면 "몸체 2" — 말풍선은 "부품 · 몸체 2")이 나옵니다.
  선 형상(와이어프레임 곡선·점 묶음)도 몸체 줄로 셉니다: 입체 줄 다음에 곡선 아이콘과 표현 이름(없으면 "선 형상 1"·"점 형상 1", 말풍선은 "부품 · 선 형상 1")으로 나오고,
  입체 하나에 선 형상이 붙은 부품도 펼칠 수 있습니다. 선 형상 줄도 누르면 그 선 형상만 고르고, 눈 단추는 그 선 형상만 숨기며, 3D에서 몸체 단위로 선을 누르면 그 줄을 고름으로 보입니다
  (속성 탭에는 선 형상에 부피·질량이 없다는 안내). 이름 없는 "몸체 2"·"선 형상 1"은 화면 글이라 다른 언어 화면에서 옮기고, 파일의 이름은 옮기지 않습니다.
  형상 항목이 하나인 부품에는 줄을 더하지 않고, 몸체 줄은 처음에 접어 둡니다(몸체가 여럿인 부품 하나짜리 파일만 처음부터 펼침).
  몸체 줄을 누르면 그 몸체를 고르고(다시 누르면 풀기, 두 번 누르면 맞춰 보기), Ctrl·⌘·Shift(여러 개 고르기 모드면 그냥 누르기)로 더하고 빼며,
  눈 단추는 그 몸체만 숨기고, 오른쪽 누르기(휴대폰은 길게 누르기)는 작업 메뉴(이것만 보기·속성 등)를 엽니다. 3D에서 몸체 단위로 누르면 나무가 그 부품을 펼쳐
  몸체 줄을 고름으로(부품 줄은 일부 고름 띠) 보이고 그 줄로 스크롤합니다. 이름 거르기 칸은 이름 있는 몸체도 찾습니다.
  고르기만 바뀌면 나무를 다시 그리지 않고 줄 표시만 고칩니다. 부품 자리 3,000개(그 가운데 600개가 몸체 셋 — 몸체 줄 1,800줄)인 합성 조립을 헤드리스 Chrome에서 재면
  3,000줄 나무 그리기가 0.12초쯤(몸체 줄을 넣기 전과 같은 수준 — 아이콘을 한 번만 읽어 복제하도록 바꿔 몸체 줄 없는 나무는 조금 빨라짐), 줄 하나 누르기가 6 ms쯤입니다.
- **여러 개 고르기**: 3D에서 **Ctrl·⌘·Shift를 누른 채 누르면** 그 부품(몸체 단위면 몸체)을 고른 것에 더하고, 이미 골랐으면 뺍니다(제품 나무 줄도 같음 — 그 마디 아래 형상 전체, 몸체 줄은 그 몸체).
  손가락 기기에서는 고른 부품 카드의 **"여러 개"** 단추, "고르기" 메뉴의 "여러 개 고르기", 작업 메뉴(길게 누르기)의 "여러 개 고르기"로 켭니다.
  켜 있는 동안은 3D와 나무 줄을 그냥 누를 때마다 더하고 빼며, 빈 곳을 눌러도 모은 것을 잃지 않습니다. 아래 띠에 모은 것과 크기, "작업"(숨기기·이것만 보기·
  흐리게·불투명도·고르기 풀기 메뉴)과 ✕(끝내기 — 고른 것은 남김)를 둡니다. Esc도 먼저 이 모드를 끕니다. 측정·면 고르기를 켜거나 새 문서를 열면 꺼집니다.
  고른 것은 "부품 N개"(몸체 단위면 "몸체 N개", 부품의 일부 몸체만 골랐으면 "부품 2개 · 몸체 1개")로 묶여 나무에 함께 표시되고, 숨기기(H)·이것만 보기(I)·나머지 흐리게·고른 부품 보기·STL/OBJ "고른 것" 내보내기·속성 탭의 물리 속성 합에 그대로 쓰입니다.
- **작업 메뉴·숨기기·이것만 보기**: 3D에서 부품을 **오른쪽 누르기**(끌어 이동하지 않을 때)하거나 휴대폰에서 측정·면 고르기가 아닐 때 **길게(0.5초) 누르면**
  그 부품을 고르고(여러 개 고르기 중이면 모은 것에 더하고) 작업 메뉴(맞춰 보기·숨기기 H·이것만 보기 I·나머지 흐리게·불투명도…·속성·여러 개 고르기·모두 보이기·고르기 풀기)를 엽니다. 제품 나무 줄도 오른쪽 누르기(휴대폰은 길게 누르기)로 같은 메뉴를 엽니다.
  **이것만 보기(격리)**는 고른 것만 남기고 3D 보기 위 가운데 띠에 무엇을 격리했는지와 "격리 풀기"(I)를 보입니다. **나머지 흐리게**는 다른 부품을 숨기지 않고
  반투명(12%)하게 두어 맥락 속에서 보고, 흐린 부품은 고르기·측정에서 빠집니다(코어 `setItemOpacity(id, a, { pickable: false })`). 나무의 "모두 보이기"는 숨긴 것과 격리를 함께 풉니다.
  **불투명도…**는 고른 부품을 100·75·50·25·10%로(반투명 차례에 그림), "불투명도 모두 되돌리기"로 되돌립니다.
  불투명도를 낮춘 부품이 있거나 나머지 흐리게 중이면 3D 누르기·작업 메뉴·두 점 측정은 반투명한 부품을 지나 그 뒤 불투명한 부품의 면을 고릅니다
  (코어 v0.23.0 `throughTranslucent` — 뒤에 불투명한 면이 없으면 예전처럼 반투명한 부품). 반투명하게 한 덮개 너머 안쪽 부품을 고르거나 재는 데 씁니다.
  둘 다 아니면 예전처럼 앞 면을 고릅니다(파일이 정한 투명 색만 있는 문서도 그대로).
  두 점 측정 중에 격리 띠의 "격리 풀기"·"모두 보이기"로 반투명 보기가 꺼지거나 불투명도로 다시 켜져도 찍은 점·Shift·화살표·잠금 단추 잠금·끌어온 점은 그대로이고
  그 자리 미리 보기부터 반투명 너머 고르기만 바뀝니다(코어 v0.24.0 `setMeasurePickThrough` — 그 전에는 붙잡기 선택을 다시 주어 잠금과 끌어온 점이 풀렸습니다).
  **부품 색 구분**은 파일 색 대신 같은 제품(이름·제품 번호)마다 한 색(골든 각 색상환)으로 칠해 회색 조립에서 부품 경계를 봅니다(`setItemColor`).
  **분해 보기**는 3D 보기 위 가운데 막대의 슬라이더(0~100%)로 부품을 조립 가운데에서 바깥쪽으로 옮깁니다(`setItemMatrix`, 표현 PMI는 제자리). 막대의 방식 단추로
  **단계별**(기본)과 **한꺼번에**를 고릅니다. 단계별은 Autodesk 뷰어의 계층 분해처럼 바깥 조립부터 한 단계씩 벌립니다: 슬라이더를 조립 깊이(단계 수)로 고르게 나눠,
  첫 구간에는 맨 위 조립 바로 아래의 하위 조립·부품이(하위 조립은 통째로) 그 조립 가운데에서 멀어지고, 다음 구간에는 하위 조립마다 그 안의 하위 조립·부품이
  그 하위 조립 가운데에서 멀어집니다. 막대에 지금 벌리는 단계("단계 2/3")를 보입니다. 자식이 하나뿐인 마디는 단계로 치지 않고, 한 단계의 이동은 100%에서
  (자리 가운데 − 부모 가운데) × 1.5입니다. 한꺼번에는 예전처럼 부품 자리마다 조립 가운데에서 함께 벌리고(평평한 조립은 두 방식이 같음), 이동이 조상 이동의 합이라
  100%에서는 두 방식이 같은 자리입니다.
  막대의 방향 단추로 **사방**(기본 — 위 규칙대로 자리 가운데가 부모 가운데에서 멀어지는 쪽)과 **X**·**Y**·**Z**(장면 축 하나로만)를 고릅니다.
  축 하나로 고르면 같은 이동에서 그 축 성분만 써서 볼트·와셔처럼 한 축에 꿴 부품을 그 축으로만 떼어 봅니다. 그 축으로는 부모 가운데와 같은 자리인 부품은 제자리이고,
  단계별에서 그 축으로 움직이는 것이 없는 단계는 건너뛰어 단계 글도 그 단계만 셉니다. 100%에서는 사방 분해 자리의 그 축 성분과 같습니다.
  방식·방향을 바꿔도 분해 정도는 그대로이고, 사방으로 되돌리면 앞의 자리로 돌아옵니다(축 고르기는 TurboCAD의 분해 보기 축 X·Y·Z, LS-PrePost의 x·y·z 방향 제한처럼
  공개 도움말에 있는 꼴을 따랐고, 축 성분만 쓰는 규칙과 빈 단계 건너뛰기는 이 앱 규칙입니다).
  방향 단추 둘째 칸 "화면"의 **가로**·**세로**·**가로세로**는 보는 방향에 수직인 축으로 벌립니다: 가로는 화면 가로(카메라 오른쪽), 세로는 화면 세로(카메라 위)
  성분만, 가로세로는 보는 방향 성분을 뺀 나머지(화면 평면)만 씁니다. 방향은 분해를 켜거나 그 단추를 누를 때의 카메라로 정해 두므로 돌려 보는 동안 부품이 따라 흔들리지 않고,
  돌린 뒤 같은 단추를 다시 누르면 지금 카메라로 다시 맞춥니다. 장면 축과 같이 그 방향으로 움직이지 않는 단계는 건너뛰고, 100%에서는 사방 분해 자리의 그 성분과 같습니다.
  축 하나(X·Y·Z·화면 가로·화면 세로)로 벌릴 때는 **같은 자리에 겹친 부품을 차례로 뗍니다**: 같은 부모 아래(단계별은 같은 단계, 한꺼번에는 모든 부품 자리)에서 그 축에 수직인
  면으로 범위가 겹치고 그 축 위 가운데가 거의 같은 부품(가운데 차가 두 부품의 그 축 반폭 가운데 작은 것 이하 — 같은 자리 볼트·와셔 묶음, 같은 축 위 겹친 원판)은
  수직 면이 가장 넓은 부품(바깥 부품)을 제 분해 자리에 두고, 나머지를 넓이 차례로 그 축을 따라 처음 비는 자리(수직 면이 겹치는 다른 부품과 100%에서 범위가 겹치지 않고
  두 반폭 합의 ¼만큼 띄운 자리 — 묶음이 움직이는 쪽, 부모 가운데에 있으면 가까운 쪽)로 옮깁니다. 옮길 거리가 (부모 반폭 + 제 반폭) × 2와 묶음 반폭 합 × 1.25
  (조립 대각선 절반까지)의 합을 넘으면 그대로 둡니다(큰 하위 조립이 장면 밖으로 날아가지 않게). 떼는 양은 그 단계의 이동에 더해 하위 조립은 통째로 먼저, 그 안은 다음 단계에 뗍니다.
  로컬 표본의 큰 조립 다섯(부품 58~106개)에서 100%에 범위 상자가 겹친 부품 쌍이 두 방식 합쳐 X 526 → 127, Y 650 → 83, Z 742 → 144쌍으로 줄고
  (사방 분해는 94쌍), 100% 장면 대각선은 조립의 1.7~2.2배에서 2.3~3.2배가 됩니다(사방 2.5배).
  분해 정도·방식·방향은 보기 링크(`exp:60,step`, 축 하나면 `exp:60,step,z`, 화면 방향이면 그 카메라 각까지 `exp:60,step,sx,0.7853982,0.5235988` — 아래)에 담깁니다.
  부품 자리 3,000개 합성 조립에서 계획(묶음 범위를 한 번 잼)과 슬라이더 한 번은 몇 ms이고(로컬 큰 조립은 계획 1.3 ms 안), 계획은 장면·방식·방향(화면 방향은 카메라 각)마다
  한 번만 세웁니다(`src/app/explode.ts` — 방식·방향 단추·단계 글 `src/app/explodebar.ts`와 함께 문서를 열 때 받음).
  측정·면 고르기를 켜면 분해를 접습니다(제자리 형상으로 잽니다). 코어는 장면을 바꾸면 겉모습을 풀므로 곡면 품질을 바꿔 다시 삼각화해도 앱이 다시 겁니다.
  저장된 보기를 고르면 카메라와 그 보기의 PMI만 바꾸고 분해 정도·방식·방향은 그대로 둡니다.
  휴대폰에서는 방식·방향 단추를 둘째 줄부터 두고(좁으면 방향 단추가 셋째 줄로, 화면 방향 칸은 그다음 줄로), 손가락 기기에서 슬라이더·방식·방향 단추·닫기가 38px 이상입니다.
- **단면 보기**: 도구 막대 "단면"에서 축(끔·X·Y·Z)을 고르면 3D 보기 왼쪽 위에 막대가 나옵니다 — 축 바꾸기, 위치 슬라이더(좌표 값 표시),
  잘라 내는 쪽 뒤집기, 끄기. 닫힌 입체는 잘린 면이 채워지고, 잘린 면을 누르면 그 부품을 고르고 "단면(자른 면) 위 점"을 보입니다(면 고르기는 하지 않음).
  위치 칸에 숫자(표시 단위)를 넣어 그 좌표에 자르고, 3D 보기 위 단면 손잡이(법선 쪽 화살표)를 끌어 평면을 법선 방향으로 옮깁니다.
  **면으로 자르기**: 면을 고른 뒤 작업 메뉴(오른쪽 누르기·길게 누르기)의 "이 면으로 자르기"나 휴대폰 면 고르기 띠의 "자르기"로 그 평면 자리에서 자르고(손잡이로 안쪽으로 밉니다),
  원기둥·원뿔·원환 면은 "축을 지나게 자르기"로 축을 지나며 눈 쪽 절반을 잘라 구멍 안을 봅니다(막대에 "면" 표시, 도구 막대 "단면 면").
  문서를 새로 열면 단면은 꺼집니다.
- **모서리 고르기**: 면 고르기 중에는 코어 윤곽선 고르기(`setPickEdges(true)` → `Pick3d.kind 'edge'`, 선분 번호 → 모서리 표)를 켜 모서리 가까이 누르면 그 B-rep 모서리를 강조하고
  길이(곡선 적분, 정확), 원은 Ø·반지름·둘레, 원호는 R·호 각·호 길이, 타원은 두 반지름, 중심·축·시작/끝 점을 측정 띠·패널·상태 막대에 보입니다.
- **면 고르기**: 도구 막대 "고르기" 메뉴의 "면·모서리"를 고르거나 **Alt(⌥)를 누른 채 누르면** 부품 고르기와 함께 누른 B-rep 면을 찾아 그 면(부품 통째 대신)과 경계 모서리(청록색)를 강조하고,
  패널 아래 띠에 면 종류(평면·원기둥 면·원뿔 면·구 면·원환 면·B-스플라인 곡면…)·STEP 번호·반지름/지름·축·법선·넓이·둘레를 보입니다. Esc로 풉니다.
  넓이·둘레는 화면용 삼각형이 아니라 해석기가 B-rep에서 구한 값입니다: 둘레는 모서리 곡선 길이를 적분해 더하고(이음선 제외),
  넓이는 평면이면 경계 곡선을 따라 그린 정리(|바깥 고리| − Σ|구멍|), 원기둥·원뿔·구·원환이면 매개변수 영역 적분입니다.
  경계에 B-스플라인 같은 곡선이 있거나 B-스플라인·회전·밀기 곡면이면 근삿값이라 "≈"를 붙입니다(면 표 `area`·`perimeter`·`exact`).
- **측정**: 도구 막대 "측정"을 켜면 3D 보기 아래 가운데 띠(넓은 화면도)에서 **두 점**과 **개체**를 고릅니다.
  두 점은 코어 측정(거리·dx·dy·dz)이고, 3D 보기 위 글자도 앱의 표시 단위·소수 자리·화면 언어로 씁니다(코어 `setMeasureFormat`).
  두 점 측정은 꼭짓점·윤곽선 끝점 말고도 **원·원호 중심**과 **모서리 가운데 점**에 붙습니다(코어 v0.8.0 `setMeasureSnap`): 모서리 표가 아는
  모든 원·원호·타원 중심을 세계 좌표(자리 변환·묶음 원점 반영)로 늘 후보로 주어 구멍 가운데 빈 곳에 커서를 두어도 중심에 붙고,
  측정 중에는 윤곽선도 골라 누른 B-rep 모서리의 끝점·곡선 길이 가운데 점·중심을 더합니다(곡선 모서리에서 꺾은선 토막의 가운데 점은 쓰지 않음 — `src/app/snap.ts`).
  곡선 길이 가운데 점은 모서리 표의 곡선 정의로 잰 곡선 위 점입니다: 원은 두 끝 각의 가운데, 타원·B-스플라인은 |C′|를 가우스–르장드르로 적분해
  길이 절반 자리를 뉴턴법으로 풉니다(개체 측정의 가운데 점 붙잡기도 같은 점 — 곡선 계산 조각을 받기 전에는 꺾은선 길이로 잰 점).
  두 끝 매개변수는 해석기가 꼭짓점을 곡선에 내려 구한 값을 모서리 표에 실어 넘기므로(원호·타원 호의 틀 x축과 두 끝 각) 화면용 float32 꼭짓점과 상관없이
  정확합니다(중심 100 mm 둘레 반지름 7.3 mm 원호에서 각 가운데와 같은 점 — 그 전에는 꼭짓점 반올림만큼 6.6e-8 mm 비켰습니다).
  코어 v0.9.0의 **추론 붙잡기**도 켭니다: 윤곽선·선 형상 두 선분이 3D에서 만나는 **교차점**(×), 첫 점을 찍은 뒤 커서 둘레 모서리로 내린 **수직 발**(⊥),
  붙잡을 점이 없을 때 첫 점에서 **X·Y·Z축 방향**(축 색 안내선). 원 중심이 512개를 넘으면 코어가 점 색인(BVH)으로 찾아 큰 조립에서도 마우스 이동이 느려지지 않습니다
  (로컬 큰 조립 — 그물 128개·원 중심 5,404개 — 에서 이동 한 번에 중앙 0.4 ms).
  곡선 모서리(원·타원·B-스플라인)에서는 코어가 고른 **수직 발**과 붙잡지 않은 **모서리 위 점**을 화면용 꺾은선(현) 위가 아니라 **B-rep 곡선 위**로 옮겨 찍습니다
  (코어 v0.14.0 `setMeasureSnap({ refine })`, `src/app/curvesnap.ts`). 수직 발은 첫 점에서 곡선으로 내린 정확한 발(곡선 위에서 (첫 점 − 발)·접선 = 0인 점 가운데
  코어 발에 가장 가까운 것)이고, 모서리 위 점은 커서 광선에 가장 가까운 곡선 위 점입니다. 둘 다 코어가 고른 토막과 앞뒤 두 토막 안에서 찾습니다(꺾은선 꼭짓점은
  곡선 위 점이라 꼭짓점마다 곡선 매개변수를 처음 쓸 때 한 번 구해 둡니다). 코어 가운데 점이 오면 그 토막 두 끝 매개변수의 가운데로 옮깁니다 — 원에서는 그 호의
  길이 가운데와 같고, 길이를 적분하지 않아 마우스 이동마다 가볍습니다(STEP은 코어 가운데 점을 꺼 두어 지금은 오지 않습니다).
  표식·찍은 점·거리·dx·dy·dz가 모두 그 점까지입니다: 시험 장면에서 B-스플라인 판 모퉁이에서 반지름 10 mm 원기둥 테두리로 내린 수직 발은 현 위 발(원에서 0.0185 mm 안쪽)이면
  24.4720 mm, 원 위 발이면 24.4609 mm입니다. 직선 모서리·곡선 정의가 없는 모서리·선 형상과 면 위 점은 그대로이고, 다듬은 점이 코어 점에서 화면으로
  붙잡기 거리(마우스 10화소, 손가락은 터치 허용 거리)를 넘으면 코어가 버리고 꺾은선 위 점을 씁니다. 붙잡지 않은 점을 곡선 위로 옮겼으면 이름은 "곡선 위 점"입니다.
  코어 v0.15.0부터는 꺾은선으로는 후보가 없던 두 자리도 곡선 위로 붙습니다. 첫 점이 곡선에서 멀면 첫 점에서 꺾은선 토막에 내린 발이 모든 토막에서 토막 밖으로
  떨어져 수직 발 후보가 없었는데, 코어가 커서 둘레 토막을 열린 후보(토막 끝)로 넘기면 같은 계산으로 곡선 위 발을 찾습니다 — 시험 장면에서 반지름 10 mm 원기둥 테두리(50토막)에서
  50 mm 떨어진 판 꼭짓점에서 내린 발이 원 위 (10, 0, 20)이고 거리는 √2000 = 44.7214 mm입니다(가장 가까운 꺾은선 꼭짓점과는 0.2 mm 떨어진 자리).
  **교차점**은 두 모서리 곡선의 3D 교차점으로 옮깁니다. 곧은 모서리는 두 끝 꼭짓점을 잇는 직선이고, 직선과 원·원과 원은 식으로(직선이 원 평면을 지나는 점,
  같은 평면이면 이차식, 두 원 평면이 만나는 직선과 원), 타원·B-스플라인이 끼면 커서 둘레 표본에서 다른 곡선까지 거리가 가장 작은 곳에서 시작하는
  두 매개변수 가우스–뉴턴법으로 풉니다. 두 곡선 위 점 사이가 허용치(두 토막 길이 합과 토막 끝 좌표 크기를 더한 값의 1e-6배)보다 멀면 3D로 만나지 않는 것이라
  붙지 않고, 같은 모서리와 두 모서리가 함께 쓰는 꼭짓점(끝점 붙잡기가 맡습니다)도 넘깁니다. 두 곧은 모서리는 꺾은선이 곧 모서리라 코어 교차점 그대로입니다.
  꺾은선끼리는 현의 처짐만큼 비켜 지나가 교차점이 없던 다른 평면의 두 곡선에도(코어의 넓힌 교차) 붙습니다 — 시험 장면에서 원기둥 테두리와 곧은 모서리·
  세로 원·B-스플라인의 교차점이 모두 1e-9 mm 안입니다. 다듬은 점은 커서 광선·첫 점과 상관없이 두 토막으로만 정해져 코어가 기억해 다시 씁니다.
  측정 중 커서 아래 붙잡을 점의 종류(꼭짓점·끝점·가운데 점·중심·교차점·수직 발·X축 방향·"X축 · 모서리 위"·"X축 · 면 위"·"잠근 X축 · 모서리 위"·끌어온 점에서 Z축·끌어온 Y축과 X축의 교차·모서리와 나란히·곡선 위 점·면 위 점)를 상태 막대와 측정 띠에 보이고(휴대폰은 정밀 조준 십자선을 끌 때),
  찍은 결과의 종류("끝점 → 수직 발" 등)는 측정 띠·패널 아래 띠·상태 막대에 함께 보입니다. 축 방향의 축은 코어가 결과에 실은 값(v0.9.1 `axisB`)을 씁니다.
  코어 v0.10.0의 **모서리와 나란히**(커서가 앞서 지나간 모서리와 첫 점에서 나란한 방향, 자홍 안내선)와 **방향 잠금**도 켭니다(SketchUp의 추론 잠금).
  끝점을 잡는 동안 Shift를 누르고 있으면 지금 방향(축·모서리와 나란히·수직 발 쪽)을 잠그고 떼면 풉니다. 화살표 →·←·↑는 X·Y·Z축, ↓는 지금 방향을 잠그고
  같은 키로 풉니다(패널·메뉴에 초점이 있으면 그쪽 키). 잠그면 첫 점을 지나는 그 선 위에만 찍고, 다른 꼭짓점을 가리키면 그 점을 선에 내린 자리를 찍습니다
  (예: Z축 잠금 + 바닥 꼭짓점 = 첫 점 바로 아래, 결과 이름 "Z축 방향 · 잠금"). 첫 점이 모서리 끝이면 그 모서리를 따라 가리키지 않고 바로 다른 끝이나
  B-rep 가운데 점 위에서 Shift를 눌러도 그 모서리 방향으로 잠급니다(벽 모서리 끝에서 높이를 잴 때 — 코어 v0.12.0이 커서 아래 점이 첫 점을 지나는 모서리 위인지 봅니다).
  첫 점이 원·타원·B-스플라인 같은 곡선 모서리의 끝 꼭짓점이고 커서가 그 모서리 위(다른 끝·가운데 점·곡선을 그린 꺾은선의 꼭짓점)에 있으면
  Shift·↓·잠금 단추는 그 끝에서의 **접선 방향**으로 잠급니다. 꺾은선 첫 토막의 방향이 아니라 해석기가 B-rep 곡선의 도함수로 구한 접선입니다
  (반지름 10 mm 원기둥 테두리에서 첫 토막과 3.6° 차이). 방향은 늘 첫 점에서 커서가 있는 곡선 쪽으로 나갑니다: 첫 점이 모서리의 시작 꼭짓점이면 모서리 방향,
  끝 꼭짓점이면 그 반대, 한 바퀴 원처럼 두 끝이 같은 꼭짓점이면 커서가 원을 그린 꺾은선 길이로 앞 절반에 있으면 원이 도는 쪽, 뒤 절반이면 거꾸로 도는 쪽입니다.
  커서 아래가 축·모서리와 나란히·수직 발이면 그쪽이 먼저이고, 반원판의 지름처럼 첫 점에서 곡선의 다른 끝으로 곧은 모서리가 이어지면
  그 끝에서는 그 모서리 방향입니다(코어 v0.12.0 모서리 끝 잠금 그대로 — 곡선 접선은 곡선 위 다른 점에서). 상태 막대·측정 띠·결과에는 "접선 방향"이라 적습니다(`src/app/tangent.ts`).
  첫 점이 곡선 모서리의 끝이 아닌 곳(코어가 주는 모서리 위 점, 곡선 가운데 점, 곡선을 그린 꺾은선의 꼭짓점)이어도 커서가 같은 모서리 위에 있으면
  Shift·↓·잠금 단추는 그 점에서의 접선으로 잠급니다. 첫 점에서 B-rep 곡선 위 가장 가까운 점을 찾아 그 자리의 접선 방향을 씁니다(곡선 위로 다듬은 첫 점이면 그 자리,
  꺾은선 위 점이면 곡선에서 조금 안쪽이라 가장 가까운 곡선 위 점). 원은 식으로, 타원은 매개변수 각에서, B-스플라인은 매듭 구간을 나눈 표본에서 뉴턴법으로 찾습니다(`src/edgecurve.ts`).
  곡선 위로 다듬은 첫 점·커서 아래 점은 꺾은선에서 현의 처짐만큼 비켜 있으므로, 꺾은선까지가 허용치 밖이어도 처짐 한도(그 모서리의 가장 긴 토막의 반) 안이면
  곡선 정의로 잰 곡선까지 거리로 그 모서리 위인지 봅니다.
  첫 점이 놓인 모서리와 커서 아래 점이 그 모서리 위인지는 코어 v0.16.0이 찍은 점·미리 보기에 싣는 **선분 식별자**(`segment`·교차점의 `other`)로 정합니다:
  첫 점이 모서리 안쪽(모서리 위 점·수직 발·교차점·꺾은선 안쪽 꼭짓점)이면 그 모서리만 보고, 커서 아래 점의 토막이 그 모서리 것이면 거리를 재지 않고 그 위로 봅니다.
  식별자는 꼭짓점을 함께 쓰는 모서리 가운데 하나만 가리키므로 첫 점이 모서리 끝(꼭짓점)이면 그 꼭짓점에 닿는 다른 곡선도 보려고 좌표로 찾고,
  식별자가 없는 점(앱이 주는 곡선 가운데 점·그물 꼭짓점·축 위 점)도 좌표로 찾습니다(실제 코어 시험에서 식별자를 지운 상태와 접선이 비트까지 같습니다).
  방향은 첫 점에서 커서가 있는 쪽입니다. 반지름 10 mm 원기둥 테두리의 30° 지점에서 코어가 잠그려는 토막(현) 방향과 2.4° 다릅니다.
  곡선 정의를 싣지 않은 모서리(B-스플라인 정의가 한도를 넘거나 옛 결과)는 꺾은선 꼭짓점에서 어림한 접선을 씁니다(시험의 타원·B-스플라인에서 0.3° 안).
  손가락 기기는 측정 띠의 잠금 단추로 잠그고 풉니다(정밀 조준 중 다른 손가락으로 눌러도 됩니다). 단추와 ↓는 커서 아래에 잠글 방향이 없으면 첫 점 뒤 마지막으로 본 방향을
  잠그고(커서가 캔버스를 떠난 뒤에도), 본 방향도 없으면 맞추는 법을 알립니다. 잠그면 그 알림을 거둡니다.
  상태 막대·측정 띠에 "X축으로 잠금"·"모서리와 나란히 잠금"·"접선 방향으로 잠금"을, 키보드 기기에는 끝점을 잡는 동안 커서 아래에 Shift로 잠글 방향이 있으면 "Shift·화살표로 방향 잠금",
  없으면 "화살표로 축 잠금"을 보입니다.
  마우스·펜 커서를 꼭짓점·끝점·중심 같은 점 위에 0.5초 머물면 그 점을 기억해(작은 십자, 최근 셋) 그 점을 지나는 X·Y·Z 축에도 붙습니다(코어 v0.16.0 **끌어온 축** —
  첫 점 전에도 되고, 첫 점 축 위에서 그 점과 나란한 자리가 먼저입니다). 이름은 "끌어온 점에서 Z축"이고 결과에도 그대로 적습니다. 손가락은 머무르지 않습니다 —
  길게 누르기는 정밀 조준이 쓰므로 끌어올 점을 따로 주지 않고, 정밀 조준 중 십자선 미리 보기는 마우스처럼 머뭅니다. 둘째 점을 찍거나 측정을 지우면 잊습니다.
  기억한 두 점의 서로 다른 축이 만나는 자리(두 모서리 끝에 차례로 머문 뒤 면 한가운데 등 — "끌어온 Y축과 X축의 교차")와 끌어온 축이 모서리와 만나는 자리
  ("끌어온 점에서 X축 · 모서리 위")에도 붙고(코어 v0.17.0), 결과에도 그 이름을 적습니다. 코어는 셋 다 축 붙잡기로 주므로 찍은 점의 `trackOther`·`segment`로 가릅니다.
  모서리 위 자리의 선분 식별자는 v0.16.0과 같아 그 점을 첫 점으로 한 곡선 접선 잠금도 그 모서리를 식별자로 찾습니다.
  첫 점을 찍은 뒤에는 첫 점의 X·Y·Z축이 커서 둘레 모서리와 만나는 자리("X축 · 모서리 위")와, 첫 점 축이나 끌어온 축이 커서 아래 면을 뚫는 자리
  ("X축 · 면 위", "끌어온 점에서 X축 · 면 위")에도 붙습니다(코어 v0.18.0 `axisEdges`·`axisFaces`). 첫 점 축 위 점이라 Shift로 그 축에 잠글 수 있고,
  결과에도 그 이름을 적습니다(코어는 축 붙잡기로 주므로 찍은 점의 `segment`·`face`로 가릅니다).
  모서리가 원·타원·B-스플라인이면 축과 꺾은선(현)의 교차가 아니라 **축 직선과 B-rep 곡선의 교차**로 옮겨 찍습니다(코어 `refine`의 `'axisEdge'`).
  곧은 모서리는 두 직선의 가장 가까운 두 점, 원·타원은 식(축이 곡선 평면을 지나는 점, 축이 평면 위면 이차식의 두 교점 가운데 코어 점에 가까운 것),
  B-스플라인은 커서 둘레 표본에서 시작하는 가우스–뉴턴법으로 풀고, 허용치와 모서리 범위는 교차점과 같습니다.
  축이 B-스플라인에 닿기만 하는 자리(접하는 곳)는 두 접선이 나란해 반복이 접점 앞에서 멈추므로, 곡선 접선이 축과 나란한 매개변수를 1차원 뉴턴법으로 따로 풀어
  그 접점(축 위로 내린 발)에 찍습니다 — 축에서 허용치보다 멀면 붙지 않고, 접점이 모서리 밖이면 끝점으로 당기지 않습니다. 시험 장면에서 판 가장 바깥에 접하는 Y축은
  접점에서 1e-11 mm 안(그 전에는 2.4e-7~4.1e-7 mm, 곡률 반지름이 5.7만 mm쯤인 평평한 곡선에서는 0.004 mm 비켜 있었습니다)이고, 축을 조금 안쪽으로 옮겨
  두 점에서 만나면 곡선 위 실제 교점 그대로입니다. 찍는 점은 축 직선 위라
  세계 축이면 남은 두 좌표가 첫 점과 정확히 같습니다(X축이면 dy·dz가 0). 끌어온 축이 곡선 모서리와 만나는 자리(v0.17.0)도 같은 계산으로 곡선 위로 옮깁니다.
  곡선을 나눈 꺾은선은 곡선보다 처짐만큼 안쪽이라, 축이 곡선 평면을 비스듬히 뚫어 곡선과는 만나지만 현과는 처짐만큼 떨어져 지나가는 자리나
  같은 평면에서 한 토막의 활꼴(현과 곡선 사이)만 지나는 자리는 꺾은선과의 교차가 없습니다. 코어 v0.20.0부터 이런 토막도 열린 후보로 넘어와 같은 계산으로
  곡선 위 교차에 붙습니다(확대해서 처짐이 반 화소보다 클 때 — 시험 장면에서 기울인 원판·타원 호·B-스플라인 위 점의 Z축, 첫 점 float32만큼인 5e-6 mm 안).
  시험 장면에서 반지름 10 mm 원기둥 테두리 이음 꼭짓점의 X축이 맞은편 테두리와 만나는 점은 원 위 1e-9 mm 안입니다(다듬기 전에는 현 위라 원보다 안쪽).
  로컬 STEP 80개 파일의 곡선 모서리 13,222자리에서 축이 곡선 위 점을 지나게 놓으면 모두 그 점과 1.5e-9 mm 안으로 다듬었고,
  축을 1e-4만큼 비켜 놓은 같은 수의 자리는 하나도 받지 않았습니다.
  축이 면을 뚫는 점도 그 면이 곡면이면 **축 직선과 B-rep 곡면의 교점**으로 옮겨 찍습니다(코어 v0.19.0 `refineFace`, `src/app/facesnap.ts`). 면 고르기에 쓰는
  면 표(그물 삼각형 → B-rep 면)로 곡면을 찾고, 원기둥·원뿔·구는 면 표에 실린 식(반지름·반각·축·중심)으로 이차식을, 원환은 곡면까지 부호 거리의 뉴턴법을 풀어
  코어 점에 가장 가까운 교점을 씁니다. B-스플라인·회전·밀기·띄운 곡면은 면 표에 식이 없습니다. 해석 워커가 해석하면서 그런 면의 곡면 정의를 다음 해석까지 들고 있다가
  (질량 속성 적분이 끝나면 되짚기 첫 짐작 격자를 버린 꼴로 — 로컬 파일 8개에서 GC 뒤 힙 차이로 재면 문서마다 3~55 kB로 해석 결과의 0.6~53%이고,
  버리기 전에는 18~182 kB로 작은 문서에서는 해석 결과보다 컸습니다),
  그런 면이 있는 문서에서 두 점 측정을 켜면 화면이 한 번 받아(구조화 복제로 잃은 클래스를 다시 붙입니다 — `src/facesurf.ts`) 해석기와 같은 곡면 계산으로
  (u, v, 직선 매개변수) 세 값의 뉴턴법을 풉니다. 곡면 계산이 든 곡면 조각(gzip 7.5 kB)은 그때만 받고, 첫 화면 JS에는 요청 몇 줄만 들어갑니다.
  한 매개변수 줄이 한 점으로 모인 극점(돔 꼭대기·둥글림 끝) 둘레에서는 코어 점을 곡면에 되짚으면 극점으로 가 뉴턴법이 멈추므로, 코어 점에서 수렴하지 않으면
  그 삼각형의 꼭짓점과 매개변수 격자에서 코어 점에 가까운 칸에서 다시 풉니다(코어 점에서 그 삼각형의 가장 긴 변 안인 교점만 — 먼 근은 받지 않습니다).
  시험의 돔 꼭대기 둘레 480자리 가운데 다시 풀기 전 262자리가 삼각형 위 점이었고 지금은 모두 곡면 위 1e-9 mm 안입니다.
  교점이 잘린 면의 경계 안인지도 봅니다. 해석기는 면을 매개변수 공간의 경계 다각형 안에서 삼각화하고 경계 꼭짓점을 모서리 위에 두므로, 그 면의 삼각형을 교점의 접평면에 펼쳐
  교점이 어느 삼각형 안(허용치는 교점과 코어 점 사이의 두 배)인지 보고, 경계 밖이면 삼각형 위 점 그대로입니다. 평면 면은 삼각형 위 점이 곧 면 위 점이라 다듬지 않습니다.
  시험 장면에서 판 꼭짓점의 X축이 반지름 10 mm 원기둥 옆면을 뚫는 점은 원기둥 위 1e-9 mm 안(다듬기 전에는 0.02 mm 안쪽)이고, 매단 판 꼭짓점의 Z축이
  B-스플라인 지붕을 뚫는 점도 곡면 위 1e-9 mm 안입니다. 로컬 STEP 83개 파일의 곡면 4,837자리(면 가운데 삼각형의 무게중심을 지나 그 면에 가장 수직인 세계 축)에서
  4,826자리를 곡면 위로 옮겼고, 옮긴 점에서 곡면까지 거리는 가장 커도 4.8e-11 mm였습니다(원기둥 2,396·원뿔 1,489·원환 623·B-스플라인 191·구 72·회전 47·밀기 8).
  옮기지 않은 11자리는 얇은 띠 모양 원기둥 면의 비스듬한 삼각형에서 축이 곡면과 만나지 않은 6자리와, 작은 B-스플라인 면의 극점 둘레에서 축이 곡면에 거의 나란히
  (곡면 법선과 cos 0.06~0.09) 곡면 밖을 지나는 5자리입니다 — 곡면 정의역 전체 고른 표본에서도 직선이 곡면에서 그 삼각형 변 길이의 1.4~1.6%보다 가까이 오지 않아
  교점이 없는 자리입니다(뉴턴법이 놓친 것이 아닙니다). 면마다 삼각형 8개로 넓힌 2,560자리(B-스플라인·회전 곡면, 파일 40개)에서도 옮기지 않은 50자리는 모두 교점이 없는 자리였고,
  다시 풀기를 넣기 전과 값이 비트까지 같습니다.
  Shift·화살표로 잠근 동안에도 잠근 선이 커서 둘레 모서리와 만나는 점과 커서 아래 면을 뚫는 점에 붙습니다(코어 v0.19.0 `lockEdges`·`lockFaces`).
  상태 막대·측정 띠·결과에는 "잠근 X축 · 모서리 위"·"잠근 X축 · 면 위"라 적습니다(축이 아닌 방향으로 잠갔으면 "잠근 방향 · 모서리 위", 곡선 접선 잠금이면 "잠근 접선 · 면 위" 꼴).
  코어 결과에는 잠금만 실리므로 찍은 점의 `segment`·`face`로 가릅니다. 잠근 선에도 위의 곡선·곡면 다듬기가 그대로 쓰입니다 — 이음 꼭짓점에서 X축으로 잠그고
  맞은편 테두리를 가리키면 원 위, 판 꼭짓점에서 X축으로 잠그고 원기둥 옆면을 가리키면 원기둥 위 1e-9 mm 안입니다. 코어 v0.20.0부터는 축이 아닌 방향(모서리와 나란히·수직·
  곡선 접선·앱이 정한 방향)으로 잠근 선도 다듬어, 원 테두리와 만나는 점은 원 위, 원기둥 옆면·B-스플라인 곡면을 뚫는 점은 곡면 위 1e-9 mm 안입니다(그 전에는 꺾은선·삼각형 위 점).
  잠그지 않았을 때는 두 선택을 켜도 끈 것과 값이 같고, 코어 v0.19.0과 v0.20.0을 견준 화면 격자 92,400자리(장면 5개 × 잠금 상태 7개)에서도
  축이 아닌 잠근 선이 원기둥을 뚫는 한 자리(이제 곡면 위)만 달랐습니다.
  잠근 동안 잠근 선이 끌어온 점(머물러 기억한 점)의 X·Y·Z축과 만나는 자리에도 붙습니다(코어 v0.21.0 `lockTracks`). 이름은 "잠근 X축 · 끌어온 점 Y축 위"이고,
  세계 축으로 잠갔는데 끌어온 점의 축이 잠근 축과 만나지 않으면(끌어온 점이 첫 점과 함께 쓰는 좌표가 없으면) 잠근 축 위 끌어온 점과 나란한 자리
  ("잠근 X축 · 끌어온 점과 나란히")에 붙습니다. 결과에도 그대로 적습니다.
  끌어온 점에서 **곧은 모서리와 나란한 선·수직인 선**에도 붙습니다(코어 v0.27.0 `trackDirs`). 커서가 앞서 지나간 곧은 B-rep 모서리(모서리 표의 직선)가 기준이고,
  나란한 선은 끌어온 점에서 그 모서리 방향, 수직인 선은 끌어온 점에서 그 모서리 직선으로 내린 수직과 X·Y·Z축을 그 모서리에 수직인 평면에 비친 방향입니다
  (세계 축과 같은 선은 끌어온 축이 맡습니다 — 그래서 축과 나란한 모서리에서는 내린 수직만 남습니다). 이름은 "끌어온 점에서 모서리와 나란히"·"끌어온 점에서 모서리에 수직"이고
  결과에도 그대로 적습니다(첫 점에서 그은 "모서리와 나란히"·"수직 발"과 따로). 원·타원·B-스플라인 모서리를 나눈 현, 종류를 모르는 꺾은선 모서리, 선 형상·PMI 선은
  기준이 되지 않아 그 위를 지나도 앞서 받은 곧은 모서리가 기준으로 남습니다(코어 v0.28.0 기준 선분 거르기 — `src/app/trackdir.ts`, 커서가 새 선분을 지날 때만 그물 표·이분 탐색 한 번).
  차례는 코어 규칙대로 점 붙잡기 → 끌어온 점 후보 → 첫 점 축·나란함 → 끌어온 축과 이것 가운데 화면에서 가까운 것(같으면 끌어온 축)이고, Shift·화살표로 잠근 동안에는 보지 않습니다.
  첫 점을 지나는 선이 아니라 Shift로 그 선에 잠그지는 않습니다. 끌어온 점은 마우스·펜으로 점에 머물러 만들므로 손가락 기기에서는 나오지 않습니다.
  화면 격자 132,000자리(장면 5개 × 상태 10개)에서 켜기 전·후 바뀐 506자리는 모두 끌어온 점이 있는 두 상태(첫 점 뒤 272자리, 첫 점 전 234자리)의 새 끌어온 점 나란함(119)·수직(387)이고,
  기준 선분은 모두 곧은 모서리였습니다(장면 선분을 끝점으로 찾아 따로 셈). 그 자리는 전에는 빈 곳 284·면 위 점 182·끌어온 축 40자리였고, 끌어온 축에서 바뀐 40자리는 모두
  끌어온 점의 선이 화면에서 더 가까웠습니다. 점 붙잡기·첫 점 축·잠근 선 위 점은 한 자리도 바뀌지 않았습니다. 거르지 않으면(0.27.0 꼴) 1,094자리가 바뀌고 그 가운데 848자리(78%)가
  원·타원·B-스플라인을 나눈 현을 기준으로 삼았습니다.
  축이나 잠근 선이 곡면을 스치며 그물 삼각형은 비켜 가는 자리(구 실루엣 둘레, 볼록한 원기둥 벽을 비스듬히 스치는 축)도 코어 v0.22.0부터 같은 계산으로 곡면 위 교차에 붙습니다.
  **붙잡지 않은 면 위 점**도 그 면이 곡면이면 커서 광선과 B-rep 곡면의 교점으로 옮겨 찍습니다(코어 v0.21.0 `'onFace'`). 이름은 "곡면 위 점"이고 결과에도 적습니다.
  광선이 곡면을 두 번 뚫으면 광선 쪽 첫 근을 씁니다. 원기둥 실루엣 둘레를 스치는 커서는 맞은 삼각형 위 점이 두 근 사이라 나가는 근(뒤쪽 면)이 더 가까울 수 있는데,
  그 자리 곡면 법선이 맞은 삼각형과 같은 쪽을 보는 근만 받습니다. 구멍 안쪽 벽처럼 오목하게 보이는 곡면에서는 맞은편 벽 위 근입니다.
  면 경계 밖이면 삼각형 위 점 그대로이고, 평면은 다듬지 않습니다("면 위 점"). 시험 장면 원기둥 옆면 위 점은 반지름 10 mm에서 1e-9 mm 안(그 전에는 0.02 mm 안쪽)입니다.
  B-스플라인 등의 곡면 정의를 워커에서 받으면 코어가 받기 전에 기억한 결과만 비워(`clearMeasureRefine`) 찍은 점·Shift 잠금·끌어온 점은 그대로 두고 지금 미리 보기부터 곡면 위로 옮깁니다.
  코어 v0.20.0(앞 판)과 견준 화면 격자 118,800자리(장면 5개 × 상태 9개)에서 바뀐 29,155자리는 곡면 위 점 16,461자리, 곡면 위로 옮겨 찍은 첫 점에서 그은 축·잠근 선 위
  점 12,687자리(원기둥 안쪽 꼭짓점을 겨눠 원기둥 옆면에 찍힌 첫 점이 0.023 mm 옮겨 갔습니다), 잠근 선과 끌어온 축의 교차 7자리뿐입니다.
  곡면 위 점은 원기둥이면 모두 반지름 10에서 1.5e-13 mm 안·광선이 들어가는 근, B-스플라인 지붕이면 곡면에서 8e-15 mm 안이고 광선을 눈 쪽으로 되짚어도 앞에 다른 교점이 없습니다.
  코어 v0.10.0의 붙잡기 점 차례 한도(`SnapPoint.order`·`setMeasureSnapLimit`)는 쓰지 않습니다 — 차례(재생 위치 같은 순서)가 있는 점을 거르는 기능이라
  STEP에는 맞는 차례가 없고, 숨긴 부품의 중심은 코어가 점의 그물 id로 이미 빼며 큰 조립은 v0.9.0 점 색인으로 충분히 빠릅니다.
  **개체 측정**은 면·모서리·꼭짓점 두 개를 눌러 잽니다: 모서리 끝점·가운데 점 가까이(마우스 9px, 터치 18px) 누르면 꼭짓점·가운데 점에 붙고, 원·원호 모서리는 중심으로 잽니다.
  평면–평면은 나란하면 거리, 아니면 사이 각, 원기둥·원뿔 면(축)끼리는 나란하면 축 사이 거리(구멍 피치), 아니면 사이 각과 최단 거리,
  원 중심–면·점–면·점–축·점–모서리·모서리끼리(나란하면 거리, 아니면 각과 최단 거리)를 B-rep 매개변수로 해석적으로 구합니다(`src/app/entmeasure.ts`).
  B-스플라인 면·곡선 모서리처럼 해석적으로 못 재는 것이 끼면 고른 면 삼각형·모서리 선분 사이 최소 거리(≈, 코어 `closestBetween`)와,
  다른 부품이면 부품 사이 최소 거리(≈, 코어 `closestPoints`)를 보입니다. 결과는 코어 덧그림(`setAnnotations` — 거리 선·각 호·원 중심 점, 값 글)으로 3D에 그리고
  측정 띠·패널 아래 띠·상태 막대에 이름표와 값을, 측정 기록 CSV에 줄을 남깁니다. 셋째 개체를 누르면 새로 재고, Esc는 누른 개체를 지운 뒤 측정을 끝냅니다.
  측정 중 단위·소수 자리를 바꾸면 덧그림 글도 바뀝니다. 문서를 바꾸면 덧그림을 지웁니다.

  (측정은 붙잡을 점·거리를 미리 보입니다) 떼면 그 자리를 누른 것으로 칩니다. 십자선의 미리 보기와 찍기는 마우스·펜과 같은 좁은 허용 거리(6px, 꼭짓점 붙잡기 10px)를 써서

  조준 중에는 3D 보기의 거리 글상자가 십자선과 손가락 자리를 비켜 그려(코어 v0.13.0 `setMeasureLabelAvoid`) 첫 점 가까이를 조준해도 거리가 가리지 않습니다.

  뷰 큐브 밑으로, 잰 뒤 보기를 옮겨 두 점 가운데가 측정 띠 높이에 오면 글상자가 띠 밑으로 들어가던 것입니다. 기본 자리(두 점 가운데의 오른쪽 위)가 이것들과

  그림 저장(PNG)은 기본 자리입니다. 뷰 큐브 자리는 코어가 알려 주는 사각형(`viewCubeRect`)을 씁니다.

    면 표 질량 속성이 없으면(면 표를 끈 해석 등) 예전처럼 화면용 삼각형으로 잰 값이라 "근삿값(화면용 삼각형)"입니다. 겉넓이는 B-rep 면 넓이의 합, 외형 크기는 화면용 삼각형으로 잰 값(≈)입니다.
    곡면 적분은 문서를 보인 뒤 해석 워커가 따로 합니다. 고른 입체의 값이 아직 없으면 부피·질량·무게중심·관성은 "계산 중…"이고 정확도 줄에 끝낸 입체 수를 보이며,
    값이 오는 대로 그 묶음만 고칩니다. 다 끝나기 전에 다른 파일을 열면 적분을 그만두고, 그 파일을 열지 못해 이 문서로 남으면 남은 입체는 화면용 삼각형 값과 안내를 보입니다.
    질량은 부품의 파일 밀도(없으면 고른 재질 — 강철·알루미늄·황동·ABS 등, 또는 g/cm³ 직접 입력)로 구하고, 무게중심은 질량을 알면 질량 가중입니다.
    질량을 알면 **관성 모멘트**도 보입니다: 무게중심 기준 주 관성 모멘트 셋(작은 것부터)과 장면 축 Ixx·Iyy·Izz(크기에 따라 kg·m²·kg·mm²·g·mm²).
    입체마다 기준점 기준 2차 모멘트를 자리 변환으로 세계로 옮긴 뒤 평행축 정리로 무게중심 기준으로 옮깁니다(주축은 야코비 회전 — `src/app/physics.ts`).
    여러 개를 골랐으면(아래 "여러 개 고르기") 그 합입니다.
  - 레이어(있을 때) — 레이어마다 켜고 끄기·항목 수, "(레이어 없음)", 모두 켜기/끄기. 파일이 숨긴 레이어(INVISIBILITY)는 처음에 꺼져 있습니다.
    이름을 누르면 그 레이어의 형상을 강조하고, 두 번 누르면 맞춰 봅니다. 레이어·눈 단추·PMI 켜고 끄기는 서로 겹쳐 따집니다(모두 켜져야 보임).
  - PMI(있을 때) — 표현 PMI 모두/하나씩 켜고 끄기(주석 평면 이름과 함께, 이름을 누르면 강조), 의미 PMI 표(치수 값·± 공차, 기하 공차 크기 | 데이텀, 데이텀).
    면에 이어진 의미 PMI는 이름을 누르면 그 면(모든 자리)을 강조하고 맞춰 봅니다(옆 숫자 = 이어진 면 수).
    저장된 보기가 있으면 단추로 그 카메라(투영·방향·창 크기)로 옮기고 그 보기의 표현 PMI만 보입니다.
  - 정보 — 문서(크기·압축·범위·삼각형), 파일 머리(FILE_NAME·FILE_DESCRIPTION·FILE_SCHEMA 등), 단위, 통계(솔리드·면·삼각화 못 한 면·삼각형·인스턴스·선 형상·레이어·PMI·읽기/삼각화 시간), 해석기 경고.
  - 패널 왼쪽 가장자리(아래 시트는 위 가장자리)를 끌어 폭(높이)을 바꿉니다. 손잡이에 초점을 두고 화살표 키로도, 두 번 누르면 기본 크기. 이 브라우저에 기억합니다.
- **상태 막대**: 형식·스키마·단위·파일 크기·삼각형·부품 수·읽은 시간과 고른 것·측정 거리.
- **내보내기**(도구 막대 "내보내기", 휴대폰은 보기 설정 → "내보내기…"): PNG 그림(지금 화면), **PNG 크게·투명 배경…**(대화 상자에서 1~4배 — 실제 화소 크기를 보이고
  기기 한도 4096² 화소를 넘으면 줄임, 바탕 화면색·투명, 측정·좌표축·단면 표시 담기·형상만 — 코어 `toBlob({ scale, transparent, overlays })`·`snapshotSize`), STL·OBJ(보이는 것 또는 고른 것 가운데 보이는 것 —
  화면용 삼각형을 세계 좌표·장면 단위로, 거울 자리는 감기를 뒤집어 바깥 법선을 지킴), 측정 기록(이 문서에서 잰 거리·고른 면)·의미 PMI 표 CSV 복사
  (화면 언어 머리 줄, 표시 단위, 엑셀용 BOM — 클립보드를 못 쓰면 파일로), 보기 링크 복사.
  손가락 기기에서 파일 공유가 되면(`navigator.canShare({files})`) 그림·STL·OBJ를 공유 시트로 건네고, 아니면 내려받습니다.
- **보기 링크**: `#view=cam:…;sec:…;sel:…;iso:1;exp:60,step` — 카메라(대상·거리·방향·투영)·단면 평면·고른 것·격리·분해만 담고 파일은 담지 않습니다.
  고른 것(`sel`)은 나무 자리 낱말을 쉼표로 잇습니다: `0/2/1`(나무 마디 통째), `0/2.3`(마디 0/2에 바로 놓인 셋째 형상 항목 — 입체 다음 선 형상 차례라
  입체가 둘이면 첫 선 형상, 나무의 몸체 줄 하나), `0/2/4-9`·`0/2.1-3`(이웃한 형제 마디·몸체를 줄여 씀). 마디 아래 형상을 모두 골랐으면 그 마디 하나로 묶고,
  나무에 없는 항목(표현 PMI 선)은 담지 않습니다(`src/app/selink.ts`). 예전 링크의 `sel:0/2/1`(마디 하나)과 입체 몸체 낱말은 이 꼴의 한 경우라 그대로 열리고,
  마디 하나만 고른 새 링크는 예전 앱에서도 열립니다(예전 앱은 선 형상 낱말만 빈 고르기로 건너뜀).
  분해(`exp`)는 정도 1~100%와 방식(`step` 단계별 · `all` 한꺼번에), 방향을 고르면 셋째 값으로 그 방향(`x`·`y`·`z`, 화면 가로 `sx`·화면 세로 `sy`·화면 평면 `sp` —
  사방이면 적지 않음)입니다. 화면 방향은 넷째·다섯째 값으로 그 방향을 정한 카메라 각(yaw·pitch, 라디안 7자리)을 담습니다 — 링크의 카메라(`cam`)는 복사할 때의 카메라라
  방향을 정한 뒤 돌려 보다 복사하면 둘이 다르기 때문입니다. 받는 쪽은 담긴 각으로 같은 방향으로 벌리고, 각이 없는 링크(손으로 줄인 것)는 링크의 카메라(곧 연 뒤의 카메라)로 정합니다.
  링크를 열면 분해 막대를 열고 그 방식·방향·정도로 벌리며, 분해가 없는 링크는 분해를 접습니다
  (예전 앱은 모르는 열쇠라 건너뛰고, 방향을 모르는 앱은 모르는 셋째 값과 그 뒤를 건너뛰어 사방으로 벌립니다 — 화면 방향을 모르는 앱은 화면 방향 링크를 사방으로 엽니다).
  고른 것 글이 1,500자를 넘으면(흩어진 부품 수백 개 — 이웃한 것은 범위로 줄어 넘지 않음) 나무 차례로 앞의 것만 담고 "형상 N개 가운데 M개만 담았습니다"로 알립니다
  (메신저·메일의 주소 길이 한도에 걸리지 않게 링크 전체를 2,000자 안쪽으로). 받는 쪽은 마디 하나면 그 마디를, 몸체 하나면 그 몸체를, 그 밖은 여러 개 고르기로 되살리고
  몸체가 든 부품은 나무에서 펼치며, `iso:1`이면 격리합니다. 받는 사람이 같은 파일(또는 `?sample`·같은 사이트 `?open=`)을 열면 그 보기를 적용하고,
  문서가 열린 뒤 해시가 바뀌면 바로 적용합니다(링크에 격리가 없으면 앞서 한 격리를 풉니다).
- **테마**: 기본은 시스템 설정을 따르고, 해·달 단추로 고른 테마는 이 브라우저에 기억합니다.
- **표시 설정**: 제목 막대의 설정(해·달) 메뉴 → "표시 설정…"에서 길이 단위(파일 단위·밀리미터·인치)와 소수 자리(0~6)를 고릅니다.
  측정 띠·패널(점·거리·면 정보·범위)·상태 막대·단면 값에 바로 쓰이고 이 브라우저(`opencad-step-display`)에 기억합니다.
  숫자는 화면 언어의 꼴로 씁니다(독일어는 소수점 쉼표, 좌표 구분 "; "). 파일에 길이 단위가 없으면 바꾸지 않습니다.
  3D 보기 위 측정 글자(코어가 캔버스에 그림)와 개체 측정 덧그림 글도 같은 단위·자리 수·언어로 그립니다.
  같은 대화 상자의 **곡면 품질**(보통·세밀 각 10°·아주 세밀 각 5°)을 바꾸면 연 파일을 다시 읽어 그 품질로 다시 삼각화하고,
  카메라·단면·고른 것·숨김·격리·밀도·측정 기록은 이어 갑니다(해석 요청 `options` → `stepToScene`의 tolerance·angleTolerance).
- **큰 모형**: 삼각형 40만 개 또는 그물 3,000개를 넘으면 코어의 나눠 올리기(`setScene(…, { incremental })`)로 GPU에 프레임마다 나눠 올리고 상태 막대에 진행률을 보입니다
  올릴 배열이 8 MB를 넘는 그물("아주 세밀" 품질의 큰 부품 등)은 코어(v0.9.0)가 4 MB씩 여러 프레임에 채웁니다.
  해석 워커는 그물 법선을 넘기기 전에 Float32 정점 3값(12바이트)에서 정규화 Int8 정점 4값(4바이트)으로 줄입니다(코어 v0.26.0 `packNormals` — `src/app/normals.ts`,
  방향 오차 0.4° 안, 같은 부품의 자리끼리 함께 쓰는 배열은 한 번만). 옮기는 버퍼·화면 쪽 메모리·GPU 버퍼에서 법선 몫이 ⅓이 되어 로컬 표본에서 가장 큰 조립이
  1.05 MB씩 작아지고, 그림은 곡면 음영의 화소 몇 개가 밝기 한 단계(1/255) 다를 뿐입니다(잰 값은 개발 절). 모형 크기와 무관하게 늘 줄입니다.
  GPU에 올린 뒤에도 법선 배열은 놓지 않고 쥡니다(코어 v0.25.0 `release: { normals: true }`를 쓰지 않음 — 줄인 뒤 가장 큰 조립도 놓을 몫이 0.52 MB이고
  되찾을 때 같은 법선을 주려면 파일을 다시 해석해야 해서입니다).
- **그래픽을 잃었을 때**: GPU·드라이버가 다시 시작되거나 휴대폰에서 탭을 오래 숨겼다 돌아와 브라우저가 3D 보기의 그래픽 문맥을 거두면,
  되찾을 때까지 "그래픽 장치가 다시 시작되어 3D 화면을 잠시 그리지 못합니다" 안내를 띄웁니다. 브라우저가 돌려주면 코어가 장면·덧그림·단면 테두리를
  스스로 다시 올리고, 앱은 안내를 거두며 "3D 화면을 다시 그렸습니다"를 잠깐 보입니다(코어 v0.25.0 `onContextLost`·`onContextRestore` — `src/app/gpucontext.ts`).
  고른 것·숨김·측정·단면은 그대로입니다.
- **주소 인자**: `?sample`은 예제를 바로 엽니다. `?open=<주소>`는 같은 사이트의 파일만 엽니다(자동 확인용, 받는 동안 받은 양·진행률을 보입니다).
  자동 확인용으로 `window.opencadApp`(`state`: 열린 문서 이름·해석 끝났는지·진행률·삼각형 수·고르기 단위·여러 개 고르기·고른 항목·고른 몸체·고른 면·고른 모서리·측정 종류·개체 측정·선/레이어/PMI 수·압축 형식·질량 속성 적분 상태 등, `openSample()`, `openUrl()`, `cancel()`,
  `selectProduct()`, `setTheme()`, `pickAt(x, y, face)`, `setFaceMode()`, `setLayerVisible()`, `setPmiVisible()`, `setSection(axis, t)`)을 둡니다.

## 해석기 쓰는 법

```ts
import { stepToScene } from 'opencad-step';

const scene = stepToScene(bytes, {
  name: 'part.step',
  onProgress: (fraction, stage) => console.log(fraction, stage),
  // 선택(모두 기본 true): curves — 와이어프레임·곡선 형상, pmi — 표현 PMI 선·의미 PMI, faceTable — 면 표
  // glyphs?: (ch) => { strokes, advance } | null — 내장 획 글꼴에 없는 PMI 글자(한글 등)의 모양(글자 칸: 대문자 높이 6, 기준선 0). 없으면 빈 상자
});
// scene: Scene3d (opencad-viewer3d의 Viewer3d.setScene에 넘긴다), scene.meta에 제품 나무·단위 등
// scene.lines: 곡선 형상(group = 부품 이름, 나무 마디의 lineIds)과 표현 PMI 선(group 없음, meta.pmi.presentations의 id)
// meta.layers?: 레이어(이름·설명·처음 보이기·meshIds·lineIds) — Mesh3d.group은 그대로 부품 이름
// meta.pmi?: { presentations, semantic }
// meta.faceKinds·faceTables·meshFaceTable?: 그물 삼각형 → B-rep 면(src/brep.ts FaceTableData)
// meta.edgeKinds·edgeTables·meshEdgeTable?: 윤곽선 선분 → B-rep 모서리(src/brep.ts EdgeTableData) — 곡선 정의는 edgeCurve(표, 번호, edgeKinds)로 읽고
//   nearestOnCurve(정의, 점)로 곡선 위 가장 가까운 매개변수·점·접선을 구한다(src/edgecurve.ts, 좌표는 묶음 origin을 뺀 그물 좌표)
// faceTables[i].props?: 닫힌 입체의 질량 속성 [부피, 1차 모멘트 3, 2차 모멘트 6, 기준점 3, 부피 어림 오차, 구한 길](src/massprops.ts PROPS_*)
//   — 선택 props: false로 끄고, propsBudget: { minMs, share }로 적분 시간 한도를 바꾼다
// Mesh3d.closed: 닫힌 입체(단면 채우기) · Mesh3d/LineSet3d/PointSet3d.origin?: 큰 좌표일 때 묶음 원점(positions는 원점 기준)
// scene.warnings?.[0] === TRUNCATED_WARNING(같은 입구에서 가져옴)이면 끊긴 파일

// 질량 속성을 나중에 구하기: 장면을 먼저 쓰고, 적분은 조각으로 나눠(run(ms)이 true면 끝) 면 표에 넣는다
import { applyProps, stepToSceneDeferred } from 'opencad-step';
const { scene: shown, props } = stepToSceneDeferred(bytes);
while (props && !props.run(40)) applyProps(shown, props.take(), props); // 사이사이 다른 일
if (props) applyProps(shown, props.take(), props);

// 압축 STEP(gzip·ZIP)은 먼저 푼다(비동기, DecompressionStream)
import { unpackStep } from 'opencad-step';
const { bytes: step } = await unpackStep(fileBytes);
```

## 개발

```bash
npm install
npm run dev        # http://localhost:4402/ (예제 바로 열기: /?sample)
npm run typecheck
npm test           # 해석기 시험(tests/*.test.ts)과 앱 순수 로직 시험(tests/app/)
npm run build      # tsc --noEmit && vite build → dist/
npm run preview    # 빌드 결과 보기
```

시험은 `tests/stepText.ts`(본문은 `src/app/stepText.ts`)로 만든 작은 STEP 글로 돌립니다(외부 STEP 파일은 넣지 않습니다).
측정 방향 잠금 시험(`tests/app/measurelock.test.ts`)은 가짜 DOM·WebGL2(`tests/app/fakeview.ts` — 코어 저장소의 시험 도구를 줄여 옮김)로 실제 코어 뷰어를 만들어
앱의 붙잡기 선택과 포인터·키 사건을 넣고 코어가 잠그는 방향을 봅니다. 곡선 접선 잠금 시험(`tests/app/measuretangent.test.ts`)도 같은 방식으로
원기둥 테두리 원·타원 호·B-스플라인 모서리(`tests/app/curvescene.ts`)의 끝과 가운데(테두리 30° 지점·타원 호 가운데 점·B-스플라인 중간 꼭짓점)에서
앱이 코어보다 먼저 잠그는 접선을 봅니다. 곡선 위 가장 가까운 매개변수는 곡선 위 점에서 조금 비킨 점으로 1e-9 안에 맞는지 봅니다(`tests/edgecurve.test.ts`).
측정 붙잡기 다듬기 시험(`tests/app/measurerefine.test.ts`)도 실제 코어로 B-스플라인 판 모퉁이에서 원기둥 테두리로 내린 수직 발이 원 위 1e-9이고 거리 값도 그 발까지인지,
타원·B-스플라인 토막 위 점이 곡선 위인지, 직선 모서리는 그대로인지, 곡선 길이 가운데 점, 다듬은 첫 점·커서 아래 점에서의 접선 잠금을 봅니다
(순수 계산 — 꼭짓점 매개변수, 법선으로 비킨 첫 점의 발, 광선이 지나는 점, 곡선 길이 가운데 — 은 `tests/app/curvesnap.test.ts`).
코어 0.15.0 다듬기 시험(`tests/app/measurecross.test.ts`)은 원기둥 테두리와 3D로 한 점에서 만나는 곧은 모서리·세로 원·B-스플라인과 멀리 떨어진 판(`tests/app/crossscene.ts`)에서
꺾은선 토막에 내린 발이 모두 토막 밖인 먼 첫 점의 원 위 발과 거리, 세 교차점과 거리가 1e-9 안인지, 곡선 붙잡기가 없으면 두 후보가 없는지를 실제 코어로 봅니다
(순수 계산 — 교차점 식·가우스–뉴턴, 같은 평면의 직선과 원, 비켜 지나가는 둘·같은 모서리·함께 쓰는 꼭짓점·두 곧은 모서리는 없음, 열린 수직 발 — 은 `tests/app/curvecross.test.ts`).
코어 0.18.0 시험(`tests/app/measureaxis.test.ts`)은 원기둥과 옆 삼각 판에서 첫 점 X·Y축과 테두리의 교차가 원 위이고 축 위 정확히인지, 곡선 붙잡기가 없으면 현 위 점,
두 선택을 끄면 후보가 없고 첫 점 전에는 켜도 같은지, 끌어온 축과 테두리의 교차, 첫 점 X축이 옆면을 뚫는 점을 실제 코어로 봅니다
(순수 계산 — 원·곧은 모서리·타원·B-스플라인과 축의 교차, 비켜 지나가는 축·호 범위 밖 — 은 `tests/app/axisedge.test.ts`,
축·잠근 선이 B-스플라인에 접하는 자리 — 접점, 평평한 곡선, 허용치 밖·안 틈, 두 근, 접점이 모서리 끝 바로 밖 — 은 `tests/app/axistouch.test.ts`).
거리 글상자가 비킬 자리 시험(`tests/app/labelavoid.test.ts`)은 3D 보기의 측정 띠·위 띠·단면 막대만 고르고 뷰 큐브는 코어 `viewCubeRect`로 받는지(큐브를 끄면 빼는지),
크기가 바뀌면 다시 알리고 정밀 조준 자리와 합치는지,
헤드리스에서 잰 휴대폰 띠·큐브 자리를 코어 자리 고르기(`placeMeasureLabel`)에 넘기면 가리던 글상자가 비키고 겹치지 않던 자리는 그대로인지를 봅니다.
코어 0.19.0 시험(`tests/app/measurelockface.test.ts`)은 같은 장면에서 잠근 X·Y축과 테두리의 교차가 원 위인지, 잠근 X축과 잠그지 않은 첫 점 X축이 옆면을 뚫는 점이 원기둥 위인지,
축이 아닌 방향으로 잠근 선이 테두리와 만나는 점·옆면과 B-스플라인 지붕을 뚫는 점이 곡선·곡면 위인지(0.20.0), 두 선택을 끄면 0.18.0 그대로이고 잠그지 않았을 때는 켜도 같은지,
B-스플라인 지붕과 민 곡면 원기둥(`tests/app/facescene.ts`)에서 워커가 남긴 곡면 정의로 곡면 위인지를 실제 코어로 봅니다(순수 계산 — 원기둥·원뿔·구·원환 식,
B-스플라인·밀기·회전 곡면의 뉴턴법, 극점 둘레 다시 풀기와 먼 근·비켜 가는 직선, 단위 배율·묶음 원점, 곡면 정의 복제·되살리기, 잘린 면의 경계 — 은 `tests/app/facesnap.test.ts`,
워커가 들고 있는 곡면 정의의 격자 버리기는 `tests/app/propsflow.test.ts`).
코어 0.20.0 시험(`tests/app/measureopen.test.ts`)은 기울인 원판·타원 판·B-스플라인 판 위 점(한 토막 가운데 매개변수) 위 판 꼭짓점의 Z축이 곡선 평면을 뚫는 자리를
열린 교차로 곡선 위에 붙이는지(잠근 Z축도, 곡선 붙잡기가 없으면 교차 없음), 축이 아닌 방향·곡선 접선으로 잠근 선이 원 테두리와 만나는 점이 원 위인지를 실제 코어로 봅니다.
코어 0.21.0~0.23.0 시험 둘은 실제 코어로 봅니다. `tests/app/onface.test.ts`는 붙잡지 않은 원기둥 옆면·B-스플라인 지붕 위 점이 곡면 위("곡면 위 점")이고 평면 윗면은 그대로인지,
원기둥 실루엣 둘레를 스치는 광선(평범한 원기둥과 민 곡면 원기둥)에서 코어 점에 더 가까운 나가는 근 대신 들어가는 근을 주는지, 판 구멍 안쪽 벽에서 맞은편 벽 위 근인지,
축이 원기둥 삼각형을 비켜 가며 곡면만 뚫는 열린 후보(0.22.0)도 같은 교점인지, 곡면 정의를 받기 전에 미리 본 축과 지붕의 교차가 다듬기 기억을 비운 뒤 곡면 위로 옮기는지를 봅니다.
`tests/app/locktrack.test.ts`는 잠근 X축이 끌어온 점의 Y축과 만나는 점·끌어온 점과 나란한 자리와 그 이름(4개 언어 사전), 끄면 0.20.0 그대로인지,

파일을 다시 읽어 새 워커에서 통째로 다시 해석해야 했고 0.27~1.0초 걸렸습니다(그림은 처음과 화소까지 같음 — 앱 워커에 다시 해석을 맡기면 앞 문서의 적분 거리와 곡면 정의를 버리므로 따로 띄운 워커).
위치·색인에서 정점 법선을 다시 구하면 2~12 ms지만 해석 법선과의 각이 90번째 백분위 4.7~7.8°, 99번째 10~22°라 그림이 달라집니다.
얻는 것이 작고 다시 주는 길이 무거워(모형이 클수록 다시 해석 시간과 그동안의 메모리가 함께 늘고, 주소로 연 파일은 다시 받아야 함) 켜지 않았습니다.
앱·코어에서 법선을 읽는 곳은 그리기뿐입니다(개체 측정·곡면 되짚기·물리 속성·간섭·STL·OBJ 내보내기는 위치·색인과 워커의 면 표만 씁니다).
**법선 줄이기(코어 0.26.0 `packNormals` — Int8 정점 4값)를 잰 것**: 놓기 대신 해석 워커가 장면을 넘기기 전에 법선을 줄입니다(`src/app/normals.ts`, 해석기 `stepToScene`과
훑기 도구는 Float32 그대로). 위 다섯 조립과 예제 모형을 줄이기 전·후 빌드에서 새 페이지마다 열어 두 번씩 번갈아 쟀습니다(헤드리스 Chrome SwiftShader, load average 2.9~4.9).
장면이 쥔 법선 배열은 1.57 MB → 0.52 MB, GC 뒤 ArrayBuffer 뒷저장은 가장 큰 조립에서 14.90 MB → 13.85 MB(나머지 넷은 0.31~1.00 MB 적음),
GPU에 올린 버퍼(WebGL `bufferData` 크기 합)는 6.45 MB → 5.40 MB(16% 적음)이고, 워커가 넘기는 버퍼는 7~16% 작아집니다.
코어 0.28.0의 성분별 GPU 버퍼 바이트(`viewer.stats.buffers`)로 다시 재면 합이 `bufferData` 합과 바이트까지 같고(가장 큰 조립 5,402,096바이트), 같은 장면을 Float32 법선으로 푼 사본을
같은 코어의 새 뷰어에 올린 값과 견주면 법선 몫만 1.57 MB → 0.52 MB(합의 24% → 10%)로 줄고 위치 1.57·색인 2.24·윤곽선 0.82·색 0.24 MB와 버퍼 수(274개)는 그대로입니다.
나머지 네 조립은 합이 6.07 → 5.07, 5.90 → 4.90, 2.39 → 2.03, 1.98 → 1.66 MB, 예제 모형은 0.246 → 0.206 MB입니다(헤드리스 Chrome, load average 2~3).
줄이는 시간은 정점 13만 개에 약 5.8 ms로 해석 시간의 0.1~0.8%입니다(Node에서 로컬 표본 45개 — 18 kB~5.6 MB 파일 — 를 크기 고르게 골라 잼, 작은 파일은 0.2 ms 안).
워커에 해석을 보내고 결과를 받을 때까지의 시간 가운데 해석 밖의 몫은 파일마다 1~4 ms 늘었습니다(빌드마다 처음 연 파일은 80~130 ms로 흔들려 빼고 — 버퍼는 복사하지 않고 옮기므로 옮기는 시간은 같음).
그림은 맞춰 보기·3배 당겨 보기 화면 658,560화소 가운데 조립 다섯 개에서 0~41화소가 달랐고 거의 모두 밝기 한 단계(1/255)이며, 당겨 본 곡면 테두리의 몇 화소만 5~10단계입니다.
곡면이 화면을 크게 차지하는 예제 모형은 맞춰 보기에서 0.3%, 3배 당겨 보기에서 2.7%의 화소가 한 단계(가장 큰 차 2) 다릅니다. 다른 화소는 모두 곡면(음영이 바뀌는 곳)에 있고 평평한 면에는 없습니다.
같은 빌드를 다시 열면 그림이 화소까지 같고, 코어 0.25.0 빌드와 0.27.0 빌드(줄이기 전)도 화소까지 같습니다. STL·OBJ 내보내기 바이트와 간섭 검사 결과(쌍 152~326개)는 줄이기 전과 같습니다
(시험 `tests/app/normals.test.ts`가 내보내기·물리 속성·간섭·그물 속성이 같은지, 같은 부품 자리끼리 줄인 배열을 함께 쓰는지, 방향 오차가 0.4° 안인지를 봅니다).
줄이는 비용이 해석 시간에 견줘 작고 그림 차이가 모형 크기와 무관하게 눈에 띄지 않아, 작은 모형도 기준 없이 늘 줄입니다.
CI의 휴대폰 검사가 재는 JS는 같은 빌드의 vite gzip 값보다 1.2 kB쯤 큽니다(CI의 압축 차이와 응답 머리).
서비스 워커는 이 조각들도 미리 담아 오프라인에서 엽니다.

**공용 사이트 도구**: 다섯 언어 페이지·검색 정보·사이트맵·내용 수정일·언어별 앱 정보·서비스 워커 빌드, 공용 번역기, 언어 메뉴, 서비스 워커 등록·새 판 알림,
방문 통계, 휴대폰 성능 비교 명령은 다른 OpenCAD 앱과 함께 쓰는 [opencad-site-kit](https://github.com/GyuTae-Kim/opencad-site-kit)
(`github:GyuTae-Kim/opencad-site-kit#v0.1.4`, 잠금 커밋 `a1de400`, 빌드 때만 써서 `devDependencies`)에 있습니다.
이 앱에만 있는 값은 `tools/site.mjs`(앱 정보 원본, 서비스 워커 판 이름 짓기)와 `tools/sw-source.mjs`(서비스 워커 본문 — 돌려주는 글이 sw.js에 그대로 들어갑니다)에 둡니다.
`check:seo`·`check:i18n`·`test:seo`·`update:content-dates`와 휴대폰 성능 예산 검사는 도구의 `opencad-site` 명령입니다. 도구 판을 올릴 때는 빌드 결과를 견줍니다.

```bash
npx vite build && cp -R dist .runtime/dist-before                                        # 올리기 전
npm install -D "opencad-site-kit@github:GyuTae-Kim/opencad-site-kit#<태그>"               # package.json·잠금 파일을 함께
npx vite build && npx opencad-site compare-dist .runtime/dist-before dist                 # 바뀐 파일과 처음 다른 곳
```

도구의 판 설명에 적힌 것 밖의 차이가 없으면, 스크립트가 바뀐 경우 내용 수정일을 갱신하고 빌드·시험을 돌립니다.

### 실제 파일 훑기

로컬에 있는 STEP 파일을 앱과 같은 해석 길(`parseStepFile` — 압축 풀기, STEP인지 가리기, `stepToScene`)로 모두 열어 보고 결과를 모읍니다.
표본 파일은 저장소에 넣지 않으므로 각자 가진 폴더를 줍니다.

```bash
npm run sweep -- --dirs ~/cad:~/Downloads --out .runtime/sweep/before        # 표본 폴더(쌍점으로 구분)
npm run sweep -- --dirs ~/cad:~/Downloads --out .runtime/sweep/after --quality normal,fine,finest
npm run sweep:compare -- .runtime/sweep/before .runtime/sweep/after           # 바뀐 파일만 보기
```

- 폴더를 재귀로 훑어 `.stp` `.step` `.p21` `.stpz` `.stp.gz`와, 안에 STEP이 든 `.gz` `.zip`만 고릅니다. 내용(sha256)이 같은 파일은 한 번만 엽니다.
  숨은 폴더와 `node_modules`는 건너뜁니다.
- `--dirs`가 없으면 환경 변수 `OPENCAD_SWEEP_DIRS`를 보고, 둘 다 없으면 쓰는 법만 보이고 끝납니다(CI에서는 돌지 않습니다). `--list`로 파일 목록을 줄 수도 있습니다.
- `--quality`에는 앱의 곡면 품질 이름(`normal` `fine` `finest`)이나 각도(`20` `10` `5` — 최대 각만 바꿉니다)를 쉼표로 여러 개 줍니다.
  `--jobs`는 일꾼 수, `--limit`은 열 파일 수, `--timeout`은 파일 하나의 시간 한도(초)입니다.
- 앱처럼 질량 속성은 연 뒤 따로 적분합니다. 기록의 `ms`는 문서를 여는 시간(적분 빼고), `propsMs`는 그 뒤 적분 시간이고 요약에 둘 다 백분위로 남깁니다.
- 기록의 `x`에는 해석 워커가 화면으로 넘기는 양(이전하는 버퍼 바이트 합), 모서리 표와 그 가운데 곡선 정의의 바이트, 끝 접선을 아는 곡선 모서리 수와
  그 가운데 곡선 정의로 접선을 구하는 수를 적고, 요약에 합·백분위·최대로 남깁니다.
  로컬 표본 2,085개에서 곡선 정의는 모서리 표를 27.8 MiB에서 32.4 MiB로(+17%), 전송량 합을 222.2 MiB에서 226.8 MiB로(+2.1%, 파일마다 p90 +2.6%, 최대 +24%) 늘렸고,
  곡선 모서리 117,673개가 모두 정의로 접선을 구했습니다(B-스플라인 한도를 넘는 것 없음). 정의를 만드는 시간은 곡선 정의가 가장 큰 30개 파일에서도
  문서 여는 시간의 0.2% 안입니다.
  원호·타원 호에 틀 x축과 두 끝 매개변수 각(수 다섯, 40바이트)을 더 실은 뒤에는 로컬 표본 1,864개에서 곡선 정의가 2.34 MiB에서 4.67 MiB, 모서리 표가
  25.70 MiB에서 28.02 MiB(+9.0%), 전송량 합이 188.19 MiB에서 190.51 MiB(+1.2%, 파일마다 중앙 +1.1%, p90 +2.8%, 최대 +4.0%·94 KiB)가 되었습니다.
  한 바퀴 원은 끝이 없어 싣지 않습니다(실으면 전송량 합 +2.1%). 분류·예외·품질 지표·질량 속성 지문은 하나도 바뀌지 않았습니다.
- 결과 폴더(기본 `.runtime/sweep/<날짜-시각>`)에는 `records.jsonl`과 `summary.json`이 생깁니다. `records.jsonl`은 파일과 품질마다 한 줄이고 열쇠는 내용 해시입니다
  (경로는 이 로컬 결과에만 적습니다). `summary.json`에는 경로 없이 분류별 개수, 판(AP)별 개수, 오류와 경고 코드, 시간 백분위, 품질 지표를 적습니다.
  결과가 이미 있으면 `--resume`(이어서)이나 `--force`(새로)를 줍니다. 비교 기준으로 남길 결과는 `--keep`으로 표시합니다.
- 품질 지표는 감기가 어긋난 입체, 부피가 음수인 입체, 접힌 삼각형(0.1% 넘는 파일 수와 가장 큰 개수 비율과 넓이 비율), 입체가 되지 못한 닫힌 껍질,
  B-rep 넓이와 크게 다른 면, 삼각형 합, 실패 면, 예외입니다. 닫힌 입체의 질량 속성(곡면 적분 정확·근삿값 섞임·삼각형으로 되돌림·시간 한도 수,
  근삿값의 최대 어림 오차, 화면용 삼각형 부피와의 최대 차)과 값 지문(모든 입체의 질량 속성 float64 비트를 이은 FNV-1a 64비트)도 함께 적습니다.
  `sweep:compare`는 구한 길별 입체 수와 값 지문도 견줘, 해석기를 고친 뒤 질량 속성이 한 비트라도 바뀐 파일을 보입니다.
- `sweep:compare`는 같은 해시와 품질끼리 짝지어 분류가 바뀐 파일, 새 예외, 지표가 바뀐 파일(위 20개)과 요약 값을 전후로 보입니다.
  출력에는 해시 앞 12자만 나옵니다(`--paths`를 주면 로컬 경로도). `--fail-on-change`를 주면 바뀐 것이 있을 때 1로 끝납니다.

### 휴대폰 검사

끌어오기 요청마다 `.github/workflows/mobile-validation.yml`이 PR 바탕(기준)과 PR(후보)을 같은 CI에서 빌드합니다. 휴대폰 첫 화면을 Lighthouse로 세 번씩 재서
중앙값 표를 작업 요약에 남깁니다(압축해서 주는 미리 보기 서버와 표는 공용 도구의 `opencad-site serve-performance`·`performance-summary` —
기준 빌드 뒤 이 커밋으로 돌아와 `npm ci`를 다시 해 명령을 찾습니다).
후보 중앙값이 `tools/performance-budget.json`의 예산을 넘으면 실패합니다(공용 도구의 `opencad-site check-performance-budget`). 지금 예산은 성능 90 이상, 접근성과 SEO 100,
FCP 2초, LCP 2.2초, TBT 300ms, CLS 0.02, JS 88 KiB 이하입니다(코어를 나눠 받은 뒤 로컬 중앙값 82 KiB — 전에는 135 KiB). 예산을 바꿀 때는 그때 잰 중앙값을 같은 파일의 `note`에 적습니다.

이어서 playwright-cli로 휴대폰 화면(390×844, 손가락)에서 쓰는 흐름을 확인합니다(`tools/mobile-browser-check.js`, 판정은 `tools/check-browser-result.mjs`).
파일 고르기로 합성 표본(`tools/mobile-sample.stp`)을 열고, 최근 문서 다시 열기, 예제 열기, 두 번 눌러 거리 재기, 끌어다 놓기, `?open=`과 `?sample`,
없는 주소를 열 때의 알림까지 봅니다.

로컬에서는 `npm run build` 뒤 `dist`를 `.runtime/performance/candidate`(와 `baseline`)로 복사하고, Lighthouse와 playwright-cli를
`npm install --prefix .runtime/mobile-audit --no-package-lock lighthouse@13.5.0 @playwright/cli`로 받아 워크플로의 "Compare cold mobile loads" 단계 명령을 그대로 돌립니다.
끝에 `npx opencad-site check-performance-budget .runtime/performance`로 예산을 봅니다.

`main`에 push하면 `.github/workflows/deploy.yml`이 typecheck → test → build를 거쳐 `dist/`를 `gh-pages` 가지에 올립니다

## 검색·공유 메타데이터와 콘텐츠 수정일

`site/metadata.json`을 공통 원본으로 삼아 Vite 플러그인이 제목·설명·canonical·Open Graph·Twitter Card·JSON-LD를 초기 HTML에 넣습니다. 같은 원본으로 앱의 공개 주소를 담은 `sitemap.xml`도 생성합니다. 공유 이미지는 각 앱의 `public/og-opencad.jpg`이며 앱 파일과 함께 배포합니다. `robots.txt`는 같은 호스트 루트(`https://gyutae-kim.github.io/robots.txt`)의 설정이 적용됩니다.

`site/content-history.json`에는 실제 콘텐츠 수정 시각과 지문을 저장합니다. 초기 HTML 본문·메타데이터·공유 이미지와 빌드된 앱/워커 JavaScript·CSS를 비교하므로 앱 기능이 바뀌면 날짜 갱신이 필요합니다. 수정일 자체와 소스 맵은 비교에서 제외합니다.

1. 콘텐츠를 변경한 실제 UTC 시각을 기록하고 `npm run update:content-dates -- --at YYYY-MM-DDTHH:mm:ssZ`를 실행합니다.
2. `npm run build`로 다시 빌드합니다. 변경되지 않은 콘텐츠는 기존 날짜를 유지하며, 날짜가 오래되었거나 잘못된 경우 SEO 검사가 실패해 배포를 막습니다.
3. `npm run test:seo`와 기존 테스트를 실행하고 메타데이터·수정일 기록을 함께 커밋합니다.

일반 빌드나 배포 시각으로 날짜를 자동 갱신하지 않습니다. `sitemap.xml`의 `lastmod`와 앱 구조화 데이터의 `dateModified`는 동일한 기록을 사용합니다. 배포 뒤에는 앱·사이트맵·공유 이미지의 실제 공개 응답을 확인하고, 포트폴리오 통합 사이트맵의 연결 날짜도 새 앱 사이트맵과 맞춥니다. 사이트맵 게시와 검색엔진의 실제 수집·색인 완료는 별도로 확인합니다.


## 다국어 UI와 정적 소개

한국어 기본 주소와 영어(`/en/`), 일본어(`/ja/`), 중국어 간체(`/zh-CN/`), 독일어(`/de/`) 페이지를 제공합니다. 각 언어의 소개 본문과 검색·공유 메타데이터를 빌드할 때 생성하며, `hreflang`과 사이트맵이 같은 페이지의 언어들을 연결합니다. `site/locales/*.json`에 한국어 원문과 번역을 저장하고, 브라우저는 선택한 언어의 사전만 내려받습니다. 방문 중 외부 번역 서비스는 호출하지 않습니다.

우측 상단 지구본 아이콘에서 언어를 선택합니다. 방향키로 이동하고 Escape나 바깥 클릭으로 닫을 수 있습니다. 언어 선택은 URL에 반영하며, 열린 문서나 편집 상태를 다시 만들지 않고 화면 문구·접근성 설명·오류·도움말을 갱신합니다. 명령 식별자·입력값·파일명·모델 이름·원본 도면의 문자는 번역하지 않습니다. 새 데이터 이름을 표시하는 요소에는 `translate="no"`를 지정하고, UI 문구의 `{0}` 같은 변수 자리를 변경하지 마세요. 여러 줄 메시지와 새 한국어 문구도 번역 사전에 추가해야 합니다. ` · `로 이은 문장은 짧은 변수 문구(예: `제품 번호 {0}`)가 뒤 조각까지 그대로 잡으면 조각마다 따로 옮깁니다(남는 한국어가 적은 쪽을 고름 — 잡은 이름은 여전히 그대로). 해석기 경고 안의 까닭 목록("삼각화하지 못한 면 3개 / 100개 (경계 고리 없음 2, 평면 삼각화 실패 1)")은 문장 틀의 자리 값이라 그대로 남으므로, 화면에서 까닭 조각을 따로 감싸 조각마다 사전으로 옮깁니다(`src/app/warnparts.ts`).

`npm run test:i18n`은 언어 전환과 문서 데이터 보존을, `npm run check:i18n`은 다섯 언어의 정적 소개·canonical·언어 링크·사전 변수·에셋 경로를 검사합니다. 번역이나 앱을 수정하면 기존 콘텐츠 수정일 갱신 절차를 따른 뒤 다시 빌드합니다. 자동 번역 초안의 주요 메뉴와 제품명은 교정했으며, 긴 기술 설명에는 추가 원어민 감수가 필요합니다.
